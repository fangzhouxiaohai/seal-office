# 2.8.1 外部办公程序依赖盘点

对应《2.8.1 升级计划》第十一节。本文记录 2.8.1 改造起点时仍依赖 LibreOffice / `soffice` 的全部路径、各自承担的格式，以及自主实现的替换方案和状态。**结论：截至本次提交，下表路径尚未替换，第十一节仍阻断 2.8.1 发版。**

可重复的盘点命令：

```bash
node scripts/check-office-runtime-free.cjs --check
```

该命令扫描产品源码、安装包配置、持续集成与部署脚本（不含历史报告和旧版本验收记录），仍有引用时以非零退出。2026-11-28 在 9cb3905 之上运行：34 个文件、84 处引用。全部替换完成后它应输出 0 并通过，届时再把它加入 `npm run test:run`。

## 一、运行时调用路径

| 端 | 位置 | 现状 |
| --- | --- | --- |
| 桌面（三平台） | `main/office/nativeRuntime.js` 定位引擎：Windows 用安装包内置 `office-runtime/program/soffice.com`，Ubuntu 用 `/usr/bin/libreoffice`，macOS 用 `/Applications/LibreOffice.app` | 缺失时提示用户安装或重装 |
| 桌面 | `main/office/nativeConversion.js` 以独立配置无头运行 `soffice --convert-to`，90 秒超时后结束进程树 | 被 `compatibleFormats.js` 的读写入口调用 |
| 桌面 | `main/office/compatibleFormats.js`：非 OOXML 兼容格式先转 DOCX／XLSX／PPTX 再交给自有编解码器；写出时先生成 OOXML 再转目标格式 | 经 `office.readCompatible` / `office.writeCompatible` 通道 |
| 桌面 | 文字编辑器 PDF：`renderer/src/editor/wordPdf.ts` 的 `wordPdfRoute` 在分栏、竖排、域、修订、受保护内容和多节版式时走 `writeCompatible('word','pdf')`（即 soffice）；其余走 Chromium `printToPDF` | 打印预览与导出 PDF 共用 |
| 桌面 | `main/fonts/fontService.js` 额外扫描 `office-runtime/Fonts` | 运行时删除后需去掉 |
| 移动网页 | `mobile/web/nativeConversion.cjs`：表格旧格式由 SheetJS 本机读写；文字与演示的旧格式、ODF、RTF 与 PDF 需用户在设置中心配置远程“文档转换服务” | 远程服务即下方 `converter/`，服务端仍是 soffice |
| 服务端 | `converter/`（`office.cjs`、`managed.cjs`、`index.cjs`、Dockerfile、`deploy/prepare-converter-runtime.sh`、systemd 单元） | 容器与部署脚本安装 LibreOffice |

## 三、按格式的替换方案

自有模块已覆盖 DOCX／XLSX／PPTX 读写、OOXML 模板与宏文档的正文读取（`标准化OOXML`）、PRN，以及移动端基于 SheetJS 的表格旧格式。下表按现有支持的源和目标格式列出替换方向。

| 格式 | 方向 | 自主实现方案 | 状态 |
| --- | --- | --- | --- |
| XLS、XLT、XLA、XLSB、ODS、OTS、FODS、DBF、DIF、SLK、SpreadsheetML 2003 | 读 | 桌面改用移动端已在用的 SheetJS 路径（`mobile/web/nativeConversion.cjs`）生成工作簿模型，再走现有 XLSX 编解码器；补样式、合并单元格、公式与日期系统的回读校验 | 未替换 |
| XLS、ODS、FODS、DBF、DIF、SLK | 写 | 同上，由 SheetJS 写出；XLS／SLK 继续保留 65536 行、256 列上限检查 | 未替换 |
| RTF | 读写 | 基于现有 DOCX 文档模型实现 RTF 读写（段落、字符格式、表格、图片） | 未替换 |
| ODT、OTT、FODT；ODP、OTP、FODP | 读写 | ODF 为 ZIP+XML，与现有 OOXML 读写器同构；按文档模型映射段落、样式、表格、图片与幻灯片 | 未替换 |
| DOC、DOT、WPS、WPT | 读 | 实现 Word 97 二进制（CFB + FIB + 文本片段表）读取，先保证正文、段落与字符格式、表格和图片 | 未替换 |
| DOC、DOT | 写 | 二进制回写成本高，评估改为“另存为 DOCX”并提示；如需保留，按读取器反向实现 | 未替换 |
| PPT、POT、PPS、DPS、DPT | 读写 | 实现 PowerPoint 97 二进制读取（记录流、文本与图片）；写出评估同 DOC | 未替换 |
| MHT、MHTML、Word 2003 XML | 读写 | MIME 多部分 / XML 解析后转 HTML 进入现有文字模型 | 未替换 |
| Word → PDF（分栏、竖排、域、修订、多节） | 写 | 扩展 `wordPdf.ts` 的 HTML 排版与 Chromium `printToPDF` 路径覆盖这些版式，删除 `native` 分支 | 未替换 |
| 表格、演示 → PDF | 写 | 复用表格打印预览与演示导出的分页渲染，经 `printToPDF` 或现有 `pdf-lib` 生成 | 未替换 |

## 四、替换完成后要删除的内容

- `main/office/nativeRuntime.js`、`nativeConversion.js` 中的定位、调用与回退，以及“请安装 LibreOffice”类提示。
- Windows 打包的 `prepare:office-runtime` 步骤、`.upgrade-private/office-runtime` 资源与 `office-runtime-notice.txt`；Ubuntu DEB 的 LibreOffice 依赖；CI 中的 Homebrew / apt 安装步骤。
- `converter/` 服务改为调用与桌面相同的自主实现，或在移动端改为本机处理后下线。

## 五、验收要求（摘自计划）

在没有 LibreOffice、`soffice` 或其他办公转换器的干净环境中，经原有入口逐格式打开、预览、打印和导出，核对中文字体、分页、图片、表格、公式和幻灯片结果，记录已知兼容边界；同时核对安装包内容、依赖清单与运行进程。任何未替换的既有路径均阻断发版。
