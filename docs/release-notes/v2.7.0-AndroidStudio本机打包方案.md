# 2.7.0 安卓本机原生宿主方案

## 目标与源码位置

在 `android-mobile/android-studio/` 建立 Java 原生 Android 项目，由本机 Android SDK 和 Gradle 构建安装包。保留 `mobile/` 的 uni-app x 工作源码、`android-mobile/` 中原有 HBuilderX 项目文件，以及 `harmony-mobile/` 的鸿蒙项目。安卓原生项目使用 `mobile/static/office/` 最新构建资源，构建时核对版本、平台和关键文件；不会为了绕过云打包体积限制移除字体、编辑器或功能依赖。

## 宿主与网页协议

原生页面继续从旧版 `file:///android_asset/apps/__UNI__B52B65B/www/static/office/index.html` 路径加载工作台，沿用现有本地存储来源。宿主关闭任意文件路径访问，只给精确的内置工作台主页面提供桥接，外部网页在系统浏览器中打开。原有 `sealNative`、`uni.webView.postMessage` 和 `sealReceiveNative` 消息协议保持不变，逐项承接网络请求及流式响应、取消请求、系统文件选择、保存、打印、剪贴板、内置字体、工作区状态与返回键。

返回键先由网页关闭当前浮层；当网页确认底部主导航可见并保存工作区后，原生层核对本次按键序号，再将任务移到系统桌面。安卓系统启动画面显示居中海豹标识并保持到工作台就绪；原生容器不再显示第二层标识。加载失败给出明确中文错误和重试入口。

## 验收门槛

1. 构建前先验证原生桥接协议测试在缺少实现时失败；实现后运行 Java 单元测试、Gradle 编译与安装包校验。
2. 在安卓模拟器中安装并验证启动、工作台加载、五个主导航页的返回键、浮层先关闭、文件选择与保存、剪贴板、网络接口及真实文档编辑保存重开。校验 APK 含完整本地网页、字库及与本轮源码一致的资源指纹。
3. 核对旧 APK 签名和同一签名私钥。本机测试包与旧版并存，不能称其可无损覆盖旧包；不要求用户卸载有数据的旧包。正式替换旧安卓发行附件以前必须验证签名一致与保留数据覆盖安装。
4. 原 HBuilderX 云源码及已提交的云打包任务保留，直到本机原生宿主功能等价并完成签名与安装验收。

## 本机实施与实测

- Java 工程已落在 `android-mobile/android-studio/`，原 HBuilderX 工程仍在 `android-mobile/` 根目录。Gradle 8.13、安卓编译目标 36、最低版本 28；正式包保持 `com.sealoffice.mobile`、`2.7.0`、`20700`。
- 完整安卓工作台资源共 29 个实际文件、59,635,080 字节，包括编辑器、页面、依赖和两套中文字库；与 APK 内资源逐文件字节核对通过。最终调试 APK 为 46,529,760 字节，SHA-256 为 `cb4996c30a6c04fe06159b45483a3efb15f01f45b3d29539e448000f55cb70e5`。Java 单元测试及 `assembleDebug` 通过；隔离设备的冷启动录像核对到同一个系统标识画面直接进入工作台，没有第二层原生启动画面。
- 模拟器验证了原生握手、剪贴板写入、匿名分享页联网、系统导入与保存选择器的取消回传，以及旧版 `file://` 来源的本地数据库读写；通过系统选择器实际选取 26 字节测试文件，原生回传文件名和内容逐字节一致。五个底部主导航分别打开后按一次系统返回键，前台均是系统桌面。
- 旧版与本机正式 APK 的证书指纹均为 `53b13e1c76a826eb15879061e8840d9bc051156ff9ed33530339f444cd3997ad`。已取得旧版证书和别名 `__uni__b52b65b`；本轮补齐全屏阅读返回及演示放映后的正式 APK 为 41,244,296 字节，SHA-256 为 `0592e4923de7d3e945a58b77de87f2693d562b502806eb64abc004e52fe49cd4`，`com.sealoffice.mobile`、`2.7.0`、`20700` 与旧版一致。调试版继续使用 `com.sealoffice.mobile.nativeqa` 并存。`verifyReleaseSigning` 缺少签名时的失败路径与取得证书后的成功路径均已验证。
- 安卓构建工具默认忽略双下划线开头的资源目录，最初路径调整后逐文件校验发现包内没有工作台资源。按安卓官方资源忽略规则显式允许该目录后重建，最终 APK 的 29 个工作台文件与本轮 Android 构建资源逐字节一致。

## 覆盖升级与剩余设备验收

在原有模拟器的隔离克隆设备上，先打开旧版 HBuilderX 应用中的文档，记录正文，再以相同签名覆盖安装 Java 原生正式包。升级后同一文档正文保留，保存提示正常，强制停止并重新启动后仍可打开。随后再次覆盖安装本轮单启动页正式包，文档正文仍保留。原设备没有被覆盖安装。目标设备仍需完成文件实际导出字节核对、打印及复杂文档编辑重开验收。原 HBuilderX 工程继续保留。
