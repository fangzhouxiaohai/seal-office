# 2.7.0 移动端返回键与启动页修订

用户复测原始 2.7.0 Android 与 HarmonyOS 安装包后指出：底部主导航已经显示时，在“我的”等页面按系统返回键仍先回首页。源码确认网页层只在首页发送退桌面请求，原生层又以首页状态二次拦截，因此与“底部主导航可见即直接回系统桌面”的要求不符。

本次修订将返回键去向统一按当前可视区的底部主导航判断。弹窗和抽屉优先关闭；主导航可见时，网页层先备份工作区，再携本次按键序号向原生层确认退到系统桌面；主导航不可见时交给当前子页面处理，再逐级回退。原生层只接受令牌、序号和退桌面标志均正确的确认，保留重复手势过滤，不再要求当前页面是首页。工作台加载占位页改为居中展示已有海豹办公标识，不显示“正在打开海豹办公”文字；加载失败时仍显示错误说明与重新打开按钮。

补充实机问题：全屏文字阅读的门户层覆盖了主导航，但原判断仅检查主导航自身的布局矩形，导致按返回键误退桌面。现在同时检查主导航祖先的隐藏、不可交互状态、系统全屏元素和屏幕命中结果。全屏阅读关闭后才恢复主导航可见；局部被助手悬浮球遮挡时，只要仍有主标签可见，就按主标签规则处理。PDF 阅读使用相同的全屏状态处理。

演示放映还遇到安卓网页视图拒绝系统全屏、弹出“Fullscreen is not supported”的问题。安卓和鸿蒙已支持在系统拒绝全屏时继续使用现有的固定视口放映层；普通网页仍显示系统全屏失败的实际原因。放映层结束后回到演示编辑区，不直接退桌面。

已完成测试先行：原逻辑下，可见主导航的编辑器、设置页返回去向测试和非首页原生退桌面测试均失败；修复后相关单元测试通过。新增全屏阅读遮挡、不可交互祖先、系统全屏和局部悬浮球遮挡用例，文字阅读完整组件回归通过。Android Studio 调试包在隔离模拟器中验证五个主标签单次退桌面；实际打开文字与 PDF 全屏阅读后，第一次系统返回均只关闭阅读层并留在应用，第二次返回才退桌面。演示放映回退逻辑的四项单元测试通过；重新安装调试包后，放映正常开始，第一次系统返回关闭放映层并留在应用。生产移动网页的模拟鸿蒙宿主流程验证“首页、云盘、服务、模板、我的”五个主页面、仍显示主导航的编辑器及登录浮层的返回行为。该网页宿主流程不能代替 HarmonyOS 真机按键验收。

本修订保留编辑器、原生页面、功能依赖和中文字库。正式 Android APK 由 Android Studio Java 工程在本机生成，不使用 HBuilderX 云打包，也不受云打包源码 60 MB 限制；旧云打包源码 ZIP 只供追溯旧流程，不代表本轮 APK 源码。正式 APK、HAP 与网页发布分别以本轮独立验收为准；原始 2.7.0 发行标签和验收记录保留历史原貌。
