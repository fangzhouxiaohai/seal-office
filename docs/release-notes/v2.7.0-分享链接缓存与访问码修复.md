# 2.7.0 分享页面缓存与访问码修复

用户反馈分享链接在一个浏览器中显示后台登录页，更换浏览器后可以看到分享页面；输入错误访问码后，输入框消失，无法直接更正。线上只读检查确认下载页和分享接口已部署，用户提供的链接在隔离浏览器中打开的是分享页面，该链接需要访问码，但不需要账号登录。未尝试猜测访问码，也未下载或更改用户文件。

旧站点曾把 `/share/` 回落到后台首页；旧响应没有明确的禁止缓存头，浏览器可能继续复用此前保存的后台页面。本次在新生成的分享链接中加入公开的入口版本参数，凭据和解密密钥仍只放在 `#` 片段内；分享页面引用带版本参数的脚本，避免复用旧脚本。服务器分享页面和静态资源设置 `Cache-Control: no-store` 及相应安全响应头。既有链接在没有旧缓存的浏览器中继续可用；已缓存旧后台页面的浏览器可能需要刷新或清除该站点缓存，服务器无法强制替换仍在有效期内的本地缓存。

有访问码的下载页现在在提交时保留输入区；格式无效、访问码错误或下载失败时仍可直接修改并重试。只有下载成功后才切换到下载按钮区域，后续重试使用本次已确认的访问码。

验收包括：隔离浏览器先缓存旧后台，再切换服务端页面，新链接可以直接进入下载页而无缓存的旧链接仍可打开；空访问码、错误访问码、修改为正确访问码并下载的完整链路通过，下载结果与隔离测试文件逐字节一致；请求地址不包含分享凭据。模拟旧的根作用域 Service Worker 拦截后，注销该测试注册可恢复访问；当前项目及已提交历史未发现注册此类线程的代码。用户原始链接的线上浏览器验证仅检查页面与错误状态，不记录链接、访问码或文件内容。

## 线上部署与回滚

分享页已单独部署，公网旧入口、新入口和带版本参数的脚本在直连及代理访问下均核对了文件哈希、禁止缓存与安全响应头；后端发布指针、网页发布指针和后台首页哈希未变。用户提供的原链接上线后再次通过隔离浏览器检查，模拟错误码时输入框保持显示、错误提示可见且焦点回到输入框。

可重复部署命令为 `python scripts/deploy-share.py --deploy`：脚本使用项目保存的主机密钥和固定指纹校验连接，先核对线上文件与当前仓库基线，备份并校验后仅替换分享脚本、分享页面和 nginx 扩展。配置检查、重载、公网检查或关联状态检查失败时自动恢复备份并核验；若相关线上文件被其他操作同时修改，脚本会停止并报告，不覆盖其他变更。本次备份位于服务器 `/root/seal-share-deploy/20261106T031037-1782a5203316/`。`python scripts/deploy-share-rollback-check.py` 在服务器独立临时目录模拟配置检查失败，确认三份测试文件恢复和哈希一致，不修改生产配置。
