# 智能助手完整任务链路升级计划

## 目标与依据

修复 DeepSeek 高强度执行“帮我总结并重新排版”时被 1 MB 传输限制中断的问题，完善对话、会话记忆、自动压缩、生成计划、工具执行、文件候选确认、撤销及保存重开。

用户已授权直接完善及 Windows 交付，本计划在当前工作区执行。依照系统化调试、测试驱动、并行分派和完成前验证流程实施。

协议依据：实际读取 OpenAI 官方[工具调用文档](https://developers.openai.com/api/docs/guides/function-calling)和[会话上下文文档](https://developers.openai.com/api/docs/guides/conversation-state)，继续使用现有服务商的兼容聊天补全接口，不改变用户模型选择。

## 根因与已复现问题

- 网络层将所有 SSE 包装、心跳和有效文本共同计入 1 MB 上限。已用完整流式字段、长度头、心跳及普通 JSON 四类响应稳定复现。
- 长总结在解析阶段和下一轮历史验证阶段还会被 12000 字符限制拒绝。两项回归已先执行并观察到预期失败。
- 当前会话只驻留渲染组件，最多发送最近 18 条消息，没有持久记忆、模型摘要压缩或工具执行循环。
- 修改数量及文件上下文存在任意固定限制；规划和大批候选需要按范围读取、分页审阅和真实版本校验。

## 设计令牌与界面策略

延续原有办公侧栏。颜色沿用 `--brand`、`--bg-card`、`--bg-app`、`--text-1`、`--text-2`、`--border`；间距沿用 4/8/12/16/24/32 像素；圆角沿用 `--radius-control`、`--radius-card`；字体沿用微软雅黑，正文 14 像素、说明 12 像素，行高 1.55。对话为主要阅读区，任务计划、压缩记录和思考为可折叠次级区域。新对话、停止、仅规划与自动执行使用原有按钮和选择控件；候选分页避免大量节点挤占阅读区域。

## 架构与协议约定

- 流式解析不再按回复总大小拒绝正常任务；完整处理正文、思考、工具调用参数分片与结束标识，保留取消、连接中断、编码和截断校验。分批刷新界面。
- 主进程执行兼容 OpenAI 的工具循环：收到 `tool_calls` 后按调用标识返回 `role: tool` 消息，再请求模型，直到模型给出最终回复或用户停止。
- 工具白名单为 `set_plan`、`read_document`、`propose_changes`。计划真实来自模型；文档读取按范围返回。修改工具通过当前窗口桥接实际验证候选并返回结果，模型能根据失败原因修正调用。
- 文件变更依然先生成候选，用户确认后应用；原文、文档快照、工作表保护和文件归属均需校验。计划不得将等待确认冒充已写入文件。
- 会话按文件或一般对话隔离，主进程加密保存完整可见消息、模型上下文、摘要和计划；保留新对话、清除及重新打开恢复入口。
- 上下文令牌预算可配置。接近预算时调用当前模型生成摘要，保留最近轮次及完整工具调用配对；摘要失败不替换原记忆。当前文件按工具分页读取，避免每轮盲目注入全文。
- 不返回任意磁盘操作或脚本工具，不把密钥、路径及加密原文写入诊断输出。窗口销毁和停止均中止模型、摘要与等待中的工具请求。
