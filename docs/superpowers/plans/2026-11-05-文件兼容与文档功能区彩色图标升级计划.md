# 文件兼容与文档功能区彩色图标升级计划

> 本文件是下一版的设计与实施计划，供审阅后执行。当前只完成样例与源码核对、方案和效果示意；尚未修改应用、运行文件转换或发布安装包。

**目标：** 让以旧版表格扩展名交付的网页报表可以安全查看和另存；让含导入损失的文件先看到已识别内容，同时保护原件；把文字编辑器顶部功能区图标调整为与首页一致的高饱和度彩色体系。

**基线：** 当前 `package.json` 为 2.6.0。下一次发行沿用仓库发布规则确定版本号，本计划不调整版本、应用身份或签名。工作区已有其他未提交修改，实施前须先核对并保留。

**架构：** 文件内容识别在读取边界完成，再按真实类型进入现有解析器；网页表格使用隔离解析和工作表模型，不将来源网页直接注入编辑界面。导入损失由打开状态与保存保护共同约束。图标由文字功能区命令语义映射到首页现有色调，不改变编辑命令。

**技术栈：** Electron 主进程、React、TypeScript、现有表格模型与功能区组件、Vitest、主进程测试。

## 二、方案取舍

| 方案 | 文件兼容处理 | 图标处理 | 取舍 |
| --- | --- | --- | --- |
| 甲 | 继续按扩展名统一交给离线转换器 | 用样式表给所有图标统一染色 | 改动小，但无法准确区分真实旧版工作簿与网页报表；图标颜色缺少语义。 |
| **乙，推荐** | 先检测文件字节与结构；真实旧版工作簿走现有转换器，网页表格走专用安全导入；导入警告提供可见的受保护查看路径 | 按命令类别复用首页色调，文字功能区单独启用 | 对症处理两类打开障碍，兼顾原件保护和视觉一致性；需增加识别、状态及保存回归测试。 |
| 丙 | 所有不匹配文件引导用户去原软件另存 | 替换全套图标资产 | 维护简单但未解决本次无法打开的报表，图标替换面过大。 |

本计划采用方案乙。真实 `.xls`、`xlsx`、`csv` 等现有路径维持原有解析与写回规则。此轮只处理有明确证据的网页表格型 `.xls` 和“已识别但因警告无法进入查看界面”的路径，不把任意网页、损坏文件或加密文件伪装为可编辑表格。

## 三、文件打开与保存设计

### 3.1 按真实内容分流

1. 在主进程读取边界核对文件大小、扩展名与有限前缀字节。传统复合文档签名的 `.xls` 仍走现有兼容转换；确认 UTF-8 或可无损识别编码、具有网页文档结构和实际 `<table>` 的 `.xls` 标为“网页表格型旧版报表”；其余内容继续给出具体中文错误。不能只搜索 `<table>` 字符串就判定成功。
2. 网页报表只在隔离的解析文档中提取表、行、单元格文本及有限的合并单元格信息，不执行脚本、不加载外链、不显示原始网页。限制输入字节、表格数量、单元格数量和展开后的模型大小；超限时明确报原因，不返回空白表格。
3. 样例中每个数据单元格标有 `mso-number-format:\@`，表示来源刻意按文本保存。导入时应保留前导零、长编号、日期字符串、空字段、中文和实体转义；有明确数字类型的其他样例按真实类型处理。来源包含不支持的样式、公式或对象时列出具体损失，不以“导入成功”掩盖。
4. 打开入口包括首页打开、最近文档、文件拖入和资源管理器关联；它们共用同一识别结果。浏览器、移动端若使用不同读取边界，实施时按同一验收矩阵适配，不能仅在首页按钮生效。

### 3.2 有损文件的受保护查看

1. 将警告分为“可查看但保存可能丢失”和“未得到可用正文或数据”。前者允许选择“查看已识别内容”，进入明确标注来源风险的受保护状态；后者保持阻断并说明未识别部分。命名区域未导入和边框样式未导入属于前者，但必须持续展示缺失内容清单，不表示原貌完整。
2. 受保护查看状态不允许原路径写回。用户要编辑时选择另存为 `.slxls` 或 `.xlsx` 副本，再在副本中编辑；副本必须使用不同路径。取消、解析失败、另存失败均不创建误导性的已完成编辑状态，也不改原件。
3. 网页表格型 `.xls` 采用同样的来源保护。入口文案明确说明“文件实际为网页表格，已按表格内容读取；原始文件保持不变”。原始扩展名仅作来源信息，不把新副本伪称为原格式无损写回。
4. 预览页和错误弹窗使用具体中文文案，区分“格式不匹配”“文件损坏或加密”“仅部分内容可查看”“转换超时”，同时给出可执行的下一步。失败时禁止用空表格、默认数据或成功提示遮盖异常。

### 3.3 验收样例与数据保护

仓库测试使用不含业务信息的最小合成文件：带编码标记的网页表格、前导零与长编号、实体字符和中文、合并单元格、真实二进制 `.xls`、非表格网页、脚本与外链、损坏文件、超限文件以及含命名区域和非细实线边框的 `.xlsx`。真实审核报表只作为本机手工验收输入，记录散列值和行列核对结果，不提交其正文、截图中的业务明细或转换副本。验收前后核对原件散列值一致。

## 四、文字功能区彩色图标设计

以下配图是**色彩意向示意**，由现状截图生成，文字局部可能有图像生成误差；按钮名称、位置与最终验收均以现有程序界面和上方原始截图为准，不把示意图当作已实现效果。

![文字功能区彩色图标意向示意](assets/2026-11-05/文档功能区彩色图标示意.png)

| 功能语义 | 建议主色 | 表现规则 |
| --- | --- | --- |
| 打开、保存、导出 | 打开琥珀色 `#E09B06`；保存蓝色 `#2F7CF6`；导出紫色 `#9B4FE8` | 大按钮图形保持原形，配约 13% 同色浅底；同类导出保持同色系。 |
| 剪贴板、插入 | 蓝色 `#2F7CF6`、青色 `#0FA69A` | 粘贴、剪切、复制等按动作分色；不将所有小按钮做成大色块。 |
| 字体与段落 | 紫色 `#9B4FE8`、青绿色 `#0FA69A` | 颜色选择类控件显示当前所选颜色，语义主色仅用于图标轮廓；文字和字号仍保持易读。 |
| 样式、视图、审阅 | 蓝色 `#2F7CF6`、青色 `#0B9FE0`、橙色 `#F2711C` | 同一命令在不同标签保持同一颜色；禁用态回落中性灰。 |
| 删除或高风险动作 | 红色 `#EF4056` | 仅用于真正具有删除或危险语义的命令，不把普通操作标成警告。 |

配色源于 `renderer/src/styles/flatDesktop.css` 的首页色调。文字功能区六个标签均按命令标识映射颜色；共享按钮组件需有明确的文字编辑器作用域，防止表格与演示功能区意外变色。浅色、深色、悬停、按下、激活、禁用、键盘焦点和高对比度场景都须逐态检查；保留图标轮廓与中文名称双重识别，不以颜色作为唯一含义。小图标尺寸仍为现有 16 像素，大图标仍为 20 像素，现有横向滚动、分组线和编辑区选区保持逻辑不能受影响。

## 七、完成判据与边界

1. 用户提供的网页表格型 `.xls` 可查看全部 11 列、1,120 行数据；前导零、长编号、中文及空值无静默变化；原件字节和散列值不变；另存副本重新打开后抽查首、中、尾记录一致。
2. 截图所示“命名区域未导入、部分边框样式未导入”不再使已识别内容完全不可见；风险提示具体、持续可查，原件不能被有损结果覆盖。损坏、加密、无表格结构与超限文件仍明确拒绝。
3. 文字功能区六个标签采用首页同一色彩体系，按钮名称、顺序、功能、快捷键和选区行为不变；禁用态、深色主题、键盘焦点及常见缩放下均可辨识。
4. 目标测试、完整测试、类型检查和构建命令均通过，留存真实文件打开与副本往返记录，再宣称升级完成。当前计划阶段不具备上述完成证据。

网页报表型 `.xls` 的目标是安全读取表格内容和生成可编辑副本，不承诺网页样式、脚本或旧版工作簿全部对象无损转换。示意图用于确认配色方向，不代表应用已经改版。
