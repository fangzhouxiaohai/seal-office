# v1.4.0 PPT文件保存与文本格式化修复

## 修复内容

### 1. PPTX文件无法从首页打开

**现象**：点击首页"打开文件"选择pptx文件后，提示"文件内容无法识别，可能不是有效的演示文稿格式"

**根因**：HomePage.tsx 中 pptx 打开逻辑检查 `数据.html`，但 pptxCodec.js 的 `读取pptx` 函数返回的字段是 `数据.演示文稿`，字段名不匹配。

**修复**：将 HomePage.tsx 中 pptx 判断条件从 `数据.html` 改为 `数据.演示文稿`，并传入 `数据.演示文稿` 而非 `数据.html`。

### 2. PPT保存文件名显示 .json 后缀

**现象**：保存PPT时文件名显示为"未命名演示.pptx.pptx.json"

**根因**：PptEditor.tsx 的 save 命令默认路径写死为 `${文稿.name}.pptx.json`，且保存内容为 JSON 序列化而非调用 PPTX 写入器。

**修复**：
- 默认路径改为 `${基准名}.pptx`，自动去除文稿名中已有的扩展名
- 保存内容改为通过 `桥接.office.writePptx` 生成真正的 PPTX 二进制文件
- 另存为同样改为 PPTX 格式写入

### 3. PPT文本颜色设置提示"请先在画布中选中一个文本框"

**现象**：用户在文本框中选中文本后，点击字体颜色下拉框选择颜色，提示"请先在画布中选中一个文本框"

**根因**：打开颜色下拉框时，按钮的 mousedown 事件传播到画布，触发 `on选中框(null)` 清除了文本框选中状态。命令执行时 `上下文.选中框标识` 为 null。

**修复**：
- PptEditor 新增 `最近选中框标识` ref，记录最后一次选中的文本框标识
- 命令上下文中的 `选中框标识` 增加回退：`选中框标识 ?? 最近选中框标识.current`
- `取激活态` 函数同样增加回退逻辑
- 选框回调包装为 `处理选框`，同步更新 ref

### 4. PPT颜色选项太少

**现象**：字体颜色下拉框只有红色、蓝色、黑色三个选项

**修复**：扩展为 19 个常用颜色选项，包括自动颜色、标准办公色和深浅变体：

- 自动颜色、黑色、白色
- 红色、深红
- 橙色、深橙
- 黄色、深黄
- 绿色、深绿（蓝色系）
- 青色、蓝色、深蓝
- 紫色、深紫
- 灰色-80%、灰色-50%、灰色-30%

### 5. PPTX写入器改进

**根因**：pptxCodec.js 的 `写入pptx` 函数仅将文本合并为一行，未利用 pptxgen 的段落格式能力。

**修复**：改进写入逻辑，支持多段落文本（按换行符分割），正确设置字体和字号。
