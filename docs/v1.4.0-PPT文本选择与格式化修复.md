# v1.4.0 - PPT 文本选择与格式化修复

## 修复内容

### 问题1：拖选文字时文本框外壳跟着被拖动

**现象**：在 PPT 编辑器中，拖动鼠标选中文本时，整个文本框被拖动而不是选中文本。

**根因**：`SlideCanvas.tsx` 的 `处理按下` 在 mousedown 时立即设置 `拖动.current` 为拖拽状态对象，导致 `处理文本框鼠标移动` 检测 `拖动.current !== null` 直接 return，文本选择被阻塞。

**修复**：
- 将 `拖动.current` 改为带状态标识的对象：`{ 状态: 'idle', ... }`
- 在 `处理文本框鼠标移动` 中，mousemove 移动不足 5px 时保持 `idle` 状态，允许文本选择
- 超过 5px 阈值后才将状态切换为 `dragging`，激活拖拽逻辑
- 拖拽处理函数 `处理移动` 仅响应 `dragging` 状态

**修改文件**：`renderer/src/ppt/SlideCanvas.tsx`

### 问题2：选择颜色失去焦点，提示"请先选择一个画布"

**现象**：用户选中文字后点击字体颜色下拉框，选区文字消失，点击颜色选项后提示"请先在画布中选中一个文本框"或"请先选中要修改的文字"。

**根因**：
1. antd Dropdown 打开时焦点转移到 Ribbon，浏览器原生文本选区被折叠
2. mouseMove 触发后 `选中起始/结束` 被设为 0
3. 颜色命令执行时 `检测选中片段(0, 0)` 返回 null

**修复**：
- `PptEditor.tsx`：新增 `选区快照` ref，在下拉框打开前保存选区范围
- 通过 `RibbonPanel.onDropdownOpen` 回调触发快照保存
- 命令上下文新增 `选区快照` 字段
- `pptCommands.ts` 中 `text.color`/`text.bold`/`text.italic`/`text.underline` 四个命令，选区为空时回退使用快照
- `deck.ts` 中 `检测选中片段` 参数类型放宽为 `number | undefined`

**修改文件**：
- `renderer/src/ppt/PptEditor.tsx`
- `renderer/src/ppt/pptCommands.ts`
- `renderer/src/ppt/deck.ts`
