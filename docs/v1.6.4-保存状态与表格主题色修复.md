# 1.6.4 保存状态与表格主题色修复

## 修复范围

本版延续 1.6.3 的底部多标签工作区、本机办公功能与界面风格，修复保存状态误判及本程序生成的 XLSX 主题色导入误报。其他功能和文件格式边界见 [WPS 对标与已知限制](v1.6.3-WPS对标与已知限制.md)。

## 保存后关闭仍提示未保存

### 复现与根因

打开 DOCX，修改正文并保存，文件已经写入磁盘，关闭标签或程序仍可能提示未保存。

状态层原先使用 `JSON.stringify` 比较页面设置。DOCX 读取器与保存快照的属性排列顺序不同，即使纸张、方向、边距等取值一致，序列化结果也不同，因而产生错误的修改标记。另外，保存命令读取了编辑区正文，但尚未触发输入事件的内容可能没有同步至状态层。

### 修复

- 页面设置按字段实际值比较；自定义纸张和页边距逐项比较数值。
- 保存及另存为前同步编辑区实际内容，成功后以写入的快照作为保存基准。
- 关闭程序时核验最新标签状态；备份完成后报告当前未保存数量。
- 保存失败、保存期间继续输入及真实页面设置变化仍保留未保存状态。
- 同一文档连续保存时更新已有成功提示，减少提示堆叠。

## 本程序生成的 XLSX 重开误报导入风险

### 复现与根因

在本程序中创建表格，给单元格添加边框，保存为 XLSX，再打开该文件，出现“表格内容可能未完整导入”，原因包含“部分主题色或透明颜色未导入”。

ExcelJS 保存带样式的单元格时可以自动写入默认字体，其中颜色使用主题索引 `theme: 1`。原读取器只识别显式 ARGB 色值，没有解析文件中实际主题方案，因此把可还原的主题黑色误判为未导入内容。

### 修复与边界

- 从 `xl/theme/theme1.xml` 读取颜色方案，按表格主题索引顺序解析颜色。
- 支持 `srgbClr` 色值与 `sysClr` 的 `lastClr` 色值。
- 基础主题字体色、填充色以实际 RGB 导入；自定义主题颜色可以再次保存。
- 有效的显式 ARGB 色值接受大小写字母。
- 未知主题索引、缺失或无效的主题色、透明颜色以及带非零 `tint` 的主题色仍提示风险。不会用默认颜色掩盖未支持格式。
