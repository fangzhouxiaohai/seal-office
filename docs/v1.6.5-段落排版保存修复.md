# 1.6.5 段落排版保存修复

本页记录 1.6.5 的交付。后续 1.6.6 已补齐 PNG、JPEG、GIF、BMP 正文内嵌图片保存与读取，当前图片范围见 [1.6.6 修复说明](v1.6.6-文档图片保存修复.md)。

## 现象与根因

在 1.6.4 中打开或编辑含首行缩进、段前段后距、行距的文档，点击保存出现“当前文档包含尚无法写入 DOCX 的内容：段落缩进或间距”。保存没有写入磁盘，因此退出时仍提示未保存。

模型转换器将所有这类 CSS 排版统一列为未覆盖内容，保存命令据此拦截；DOCX 写入器也缺少对应属性。读取器把普通缩进和间距一并报告为导入风险，列表和空段落分支还会丢失样式。这是本程序读写链路缺漏。

## 补齐的读写链路

| 范围 | 1.6.5 支持 |
| --- | --- |
| 段落缩进 | 左右、首行、悬挂缩进；零值与负左右缩进；支持常规 px、pt、em、rem、cm、mm、in、pc 尺寸转换。 |
| 段落间距 | 段前段后距；倍数行距；固定行距与最小行距；百分比行高转换为倍数行距。 |
| 原生段落属性 | 字符单位左右、首行、悬挂缩进；行单位段前段后距；自动段前段后开关。来源绝对单位备用值也按实际属性保留。 |
| 样式继承 | 文档默认段落属性、段落样式继承和直接段落属性按字段叠加。 |
| 内容分支 | 正文、标题、列表、空段落以及简单表格单元格内的多个段落保留排版。 |
| 字符与换行 | 上标、下标、正常基线和段内软回车；普通 `w:br`、带 textWrapping 类型的软回车及 `w:cr` 均保留。 |
| 外层容器 | 浏览器增加缩进产生的 blockquote 与纯块级粘贴容器映射至实际正文，不再额外产生空段。 |
| 修改来源排版 | 比较对应 CSS 排版与导入快照。未修改时保留字符、行和自动属性；修改对应排版后去掉旧属性，写入新设置。 |

渲染层使用 `renderer/src/office/paragraphFormat.ts` 解析和校验段落排版。主进程通过 `main/office/paragraphProperties.js` 控制允许字段与取值。当前 docx 库未公开字符单位和行单位的选项，因此写入器只在有这类属性时补写 `word/document.xml`，严格核对包含表格、空行和分页符在内的实际段落顺序。不会直接写入任意 XML 字符串。

无效数值、非法自动段距开关、首行与悬挂冲突、损坏的来源排版数据会明确失败或报告风险，避免以默认数据掩盖异常。

## 格式与排版边界

本次解决常用段落格式导致的保存失败，不代表已具有完整 Word/WPS 文件兼容能力。

- DOCX 图片、图形、媒体、页眉页脚、脚注尾注、批注、修订、超链接目标、合并单元格、多分节和精确分页仍不能完整往返。水印、图表等无法可靠写回的编辑对象仍在保存前提示。
- 字符单位及行单位使用受控来源属性保留；其屏幕呈现按浏览器布局近似，自动段距也没有完整复刻 Word/WPS 的排版计算。原生属性在保存文件中保留，不承诺与外部办公软件逐像素相同。
- 未知段落属性、百分比缩进等无法准确映射的样式继续提示风险；段内分页、分栏换行及浮动对象清除属性未完整导入时也会提示。
- 当前接入 DOCX、XLSX、PPTX、PDF 及常见文本和旧版 JSON 数据。旧式 DOC/XLS/PPT、WPS 专用 WPS/ET/DPS、RTF、ODF 尚未接入。
- 其他模块范围见 [WPS 对标与已知限制](v1.6.3-WPS对标与已知限制.md)，XLSX 基础主题色支持见 [1.6.4 修复说明](v1.6.4-保存状态与表格主题色修复.md)。

导入风险提示用于保护来源文件；编辑区存在无法写回的内容时不能直接覆盖原件。保存不支持对象前，可先导出 HTML 保留编辑区内容。本次没有删去真实的格式风险提示。
