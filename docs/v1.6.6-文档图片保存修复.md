# 1.6.6 文档图片保存修复

## 现象与根因

1.6.5 在文字文档中点击“插入图片”会提示“图片无法保存为 DOCX”；插入后保存又因“图片”未覆盖项失败。这是程序实现遗漏：插图入口先提示限制，模型转换器跳过所有图片，DOCX 写入器未创建图片对象，读取器也没有解析图片关系和媒体资源。

## 补齐的链路

| 范围 | 本版支持 |
| --- | --- |
| 本机插入 | 直接选择 PNG、JPEG、GIF、BMP 文件，依据真实图片字节识别类型，再经浏览器解码校验；在原光标处插入，异步读取后若文档已切换则明确提示。 |
| 尺寸适配 | 新图片按正文或当前栏的可用宽度等比缩小；旧版只有 `max-width` 的图片在保存前记录浏览器实际显示尺寸。 |
| DOCX 写入 | 原始媒体字节内嵌到文件中，写入显示宽高和说明，按实际格式修正媒体扩展名及关系。 |
| DOCX 读取 | 恢复正文引用的包内图片、尺寸和说明，支持现代 DrawingML 内嵌图和常见 VML 行内图片。 |
| 内容顺序 | 图片与正文混排、单独图片段落、简单表格内图片和多段内容保留原顺序。 |
| 兼容表示 | 现代图与旧式备用图选择一个可读分支，避免重复；现代分支资源缺失时可选择有效备用图，未选中分支不产生无关风险。 |
| 数据校验 | 单张图片限 20 MB、文档图片累计限 100 MB；拒绝无效数据、格式不符和非法尺寸。较长图片编码不再使用会导致调用栈溢出的嵌套正则。 |
| 保存状态 | 准备图片尺寸后同步正文，以实际写入快照标记保存；准备失败或文件写入失败时显示错误，不标记已保存。 |

主要实现位于 `renderer/src/office/docImages.ts`、`renderer/src/office/docModel.ts`、`renderer/src/editor/DocEditor.tsx`、`main/office/imageData.js`、`main/office/docxImages.js` 和 DOCX 读写器。浏览器与主进程共用图片签名和尺寸校验模块。帮助手册增加了文字插图说明，并更新格式支持范围。

## 格式与排版边界

- 本版支持正文内嵌的 PNG、JPEG、GIF、常见 BMP 图片。GIF 媒体原字节保留，不承诺外部办公软件播放动画。插入时像素尺寸限宽高各 32768、累计一亿像素。
- 浮动环绕、裁剪、旋转、翻转和特效不能完整往返。导入这些属性时可显示读取到的原始图片，同时保留明确的排版风险；不能直接覆盖存在导入风险的来源文件。
- SVG、WebP、组合图形、多图组合对象和外部链接图片未完整支持；远程图片不会在打开文件时自动下载。缺失媒体或损坏数据如实报告，不替换为默认图。
- 图片段落中的分页符尚未完整导入，保留图片并报告分页风险。页眉页脚里的图片也不在本次正文图片范围内。
- DOCX 的其他保真限制、旧式格式限制仍适用。段落排版支持见 [1.6.5 修复说明](v1.6.5-段落排版保存修复.md)，其他模块范围见 [WPS 对标与已知限制](v1.6.3-WPS对标与已知限制.md)。
