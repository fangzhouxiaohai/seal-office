# 1.6.7 打开、恢复与统一弹窗

## 行为约定

| 场景 | 当前行为 |
| --- | --- |
| 打开文件成功 | 文件直接进入底部标签，不显示成功消息。首页、最近文档、文件关联和各编辑器入口一致。 |
| 正常恢复工作区 | 自动恢复标签、正文和未保存标记，不显示恢复通知或固定弹窗。 |
| 打开文件失败 | 固定错误弹窗显示实际失败原因，保留现有标签内容。 |
| 退出且有未保存内容 | 自定义应用确认弹窗，默认选中取消，确认后退出。 |
| 退出前备份失败或状态无法核验 | 自定义应用弹窗说明原因，默认保留窗口，用户明确选择后才能退出。 |
| 联系客服 | 固定客服弹窗显示联系邮箱及反馈要求，联系信息可以选择和复制。 |

文件读取失败、损坏备份、实际导入不完整和覆盖冲突继续报告原因并保护数据。系统文件选择器继续用于选择打开和保存路径；退出确认使用应用自己的样式。

## 实现

应用内固定弹窗沿用现有组件库和主题，样式统一在 `main/ui/dialog.css`。退出确认在主进程创建独立无边框子窗口，使用相同样式文件，即使编辑页无法响应也可以取消退出。

子窗口通过独立预加载脚本只读取当前确认内容和提交按钮序号。主窗口、其他窗口及无效按钮序号无法替它确认；关闭弹窗、父窗口销毁、弹窗加载失败或渲染退出都按取消处理，并清理待处理请求。

实时关闭核验和关闭前备份链路保持有效。等待用户选择期间继续阻止重复核验；取消后允许重新发起关闭检查。成功恢复提示仅在外壳消费和清除，恢复数据、模型、文件指纹和保存基线继续沿用原有存储链路。

## 设计令牌

- 颜色：沿用 `--bg-card`、`--bg-hover`、`--text-1`、`--text-2`、`--brand`、`--border` 和 `--danger`，不增加装饰色。
- 间距：8、16、24 像素，内容和底部操作之间用分隔线划分。
- 圆角：弹窗 8 像素，控件 6 像素。
- 字体：现有微软雅黑字体系统，标题 18 像素、600 字重，正文 14 像素、400 字重，正文行高 1.6。
- 层级：标题与原因是视觉重点，补充说明使用次要文字，退出操作使用危险色。
- 阴影：应用内弹窗沿用现有卡片阴影；独立退出窗口不叠加装饰阴影。

## 界面自检评审

1. 退出确认原先使用系统默认消息框，与应用的字号、主题和按钮样式不一致。改为无边框自定义子窗口，共用应用弹窗设计令牌，并在打开时同步主题。
2. 客服原先使用临时消息，信息很快消失，难以选择邮箱和持续查看。改为居中的固定弹窗，设置可选择的邮箱和清晰的关闭按钮。
3. 打开成功与恢复提示反复阻断编辑，恢复内容与提示同时争夺注意力。成功链路静默完成，未保存状态在底部标签持续表达。
4. 错误原因可能很长，固定高度窗口容易挤压操作按钮。退出窗口正文区域可滚动，底部按钮固定；应用内错误文本允许长路径换行。
5. 原先不同应用弹窗的标题、间距和底部操作分隔不统一。统一标题、正文、圆角、按钮宽度和底部区域，并补齐退出弹窗的焦点、悬停、禁用和键盘循环。
6. 便携成品验收中，退出窗口曾出现顶部偏移 21 像素、根页面滚动高度超出窗口的情况。将弹窗页面固定在窗口内，禁止根页面滚动，仅允许正文内部滚动；重新构建后顶部位置为 0，320 像素窗口的页面滚动高度为 320 像素。

完整实现位于 `main/appDialog.js`、`main/ui/`、`renderer/src/App.tsx` 及文件打开链路，源码仓库包含可直接构建的完整文件。
