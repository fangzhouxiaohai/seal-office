# 1.7.0 智能助手完整任务链路

## 修复原因

旧版将 SSE 包装、心跳和有效文字一起计入 1 MB 上限，模型正文并不长也可能被误判为回复过大。后续解析、文件上下文和修改数量还存在固定上限。本次删除这些总量限制，完整接收正文、服务商返回的思考和原生工具参数分片；按批刷新界面，大文件分页读取，大批候选分页审阅。

流式完成、连接中断、模型输出截断和主动停止分别处理。程序不把截断当作成功，也不以默认数据替代异常。

## 对话与执行

继续使用 DeepSeek、豆包、智谱、Kimi 与自定义服务商的 OpenAI 兼容 Chat Completions 接口，发送标准 `tools`，处理 `tool_calls`，通过 `tool_call_id` 回传实际 `role: tool` 结果，再请求模型继续任务。DeepSeek 同一轮工具消息所需的 `reasoning_content` 保留。

| 工具 | 实际职责 |
| --- | --- |
| `set_plan` | 模型制定或更新计划，显示步骤的等待、进行、完成、失败和待确认状态 |
| `read_document` | 按条目与字符游标读取发送时的文档快照，保持定位标识和完整连续原文 |
| `propose_changes` | 由当前文件所在窗口验证修改，成功后生成待确认候选，失败返回具体原因 |

一般对话直接回复正文。文件任务按计划读取和生成候选；可先勾选“仅生成计划”，再点击“执行计划”。成功的多批修改在主进程累计，前端始终校验完整候选，失败批次不覆盖已有成功候选。

候选支持文字替换、段落排版、单元格写入和演示文本替换。确认前比较完整文件快照，校验原文、定位、文件类型和表格保护。确认后进入编辑区，随后可撤销及保存；模型工具没有任意脚本或磁盘写入能力。候选与已保存文件分别显示状态，不将待确认报告为已经写入磁盘。

## 记忆与自动压缩

每个文件与一般对话拥有独立会话。可见对话、思考、模型消息、计划、摘要和待确认候选在本机加密保存；会话标识哈希为文件名，串行原子写入。文件路径和完整编辑快照只用于本机归属与冲突校验，不作为模型消息上传。

模型设置新增“上下文令牌”，默认 131072，可按模型实际窗口调整。接近预算时调用当前模型分批归纳历史，再合并摘要；保留最新用户目标、最近完整轮次和完整工具配对。摘要失败保留原会话并显示原因，不能伪造记忆或直接截断原文。服务商明确报告上下文超限时，缩小预算、整理记忆并减小文件读取范围后重试。

摘要调用与对话使用同一模型服务，会产生服务商规定的调用费用。估算令牌是保守预算，不代替服务商实际令牌计数。

新文件保存后绑定到实际路径；绑定重试幂等，另存后回迁合并共同历史并保留独立后续消息。目标路径已有计划和候选时归档保留，当前任务沿用来源。关闭文件再打开可以恢复对话；已过期候选不恢复。点击“新对话”清除当前会话记忆。

## 取消、中断与一致性

- 停止中断实际模型连接、摘要和等待中的窗口工具；保留已收到的内容与已成功校验的候选。
- 每项工具结果立即加密保存，同批后续工具尚未结束时，前项成功候选也可以恢复。
- 程序中断留下未返回调用时，下轮补齐“上次任务中断，工具执行结果未确认”的失败结果，再继续对话，不假称工具已经执行。
- 重复调用标识直接拒绝，连续重复相同操作停止执行；记录真实失败原因，不写入无效工具配对。
- 会话生成、确认、放弃、清除和路径绑定占用完整读改写周期，其他窗口或同文件竞争操作不能覆盖记忆。
- 所属窗口、请求和工具调用标识共同校验，不能跨窗口提交结果或取消任务。
- 每次网络请求使用独立取消信号，请求结束后解除与主任务的关联，避免连续工具和摘要请求累积取消监听器。

## 界面自检

沿用原有办公侧栏的颜色、字体、间距、圆角、按钮与明暗主题。正文为主阅读区域；计划、思考和压缩摘要使用可折叠辅助区域。

| 发现的问题 | 已修正方式 |
| --- | --- |
| 窄屏标题栏操作拥挤 | 控件允许换行并统一间距，保持新对话与模型设置可达 |
| 大批候选挤占对话与输入区域 | 每页展示 20 处，独立滚动和分页，确认入口固定可见 |
| 计划和摘要与正文竞争视觉重点 | 使用次级文字和可折叠区域，正文保留主要视觉层级 |
| 高频分片反复更新造成阅读抖动 | 首片段即时，后续每 50 毫秒合并刷新，结束、失败与停止刷新尾部 |

## 协议依据与边界

本次实际读取 OpenAI 官方[工具调用文档](https://developers.openai.com/api/docs/guides/function-calling)和[会话状态文档](https://developers.openai.com/api/docs/guides/conversation-state)，实现兼容的本地执行循环。服务商须支持所选模型的聊天补全、工具调用和对应思考参数。

程序没有回复总字节中断，但服务商的上下文窗口、输出令牌、模型权限、余额、网络和本机资源仍按实际能力处理。输入、参数、编码、完整性和工具合法性继续校验，异常通过统一自定义弹窗说明原因。当前只提供上述文件工具，云端账号、搜索、任意脚本执行及下一阶段演示功能没有列为已完成能力。

2026 年 10 月 4 日完成验证：渲染层 92 个文件、1106 项测试；主进程 28 个文件、421 项测试；打包清单 2 项测试，共 1529 项通过。类型检查、前端构建及 Windows x64 打包均成功。安装版与便携版输出到本地 `release/v1.7.0/`，通过 [GitHub 发布页](https://github.com/fangzhouxiaohai/seal-office/releases/tag/v1.7.0)提供下载及文件校验值。

Windows 解包成品与便携成品各通过 39 项实际交互核验，包括：

- 接收 1200043 字节的有效单帧元数据和 27360 字符的流式长正文，完整显示并持久保存。
- 仅规划后执行真实工具循环；原文失配返回实际错误，模型纠正后累计两批修改，不重复计数。

- 8192 令牌窗口触发分批摘要及合并，共 14 次模拟模型摘要请求；后续追问延续用户约束，完整长正文显示记录保留。
- 新对话清除当前记忆；正常与减少动态模式都能停止真实网络连接并保留已收到的思考。
- 安装完整性通过，关闭前实时核验未保存数量为零、工作区备份成功；所有窗口关闭，两个成品均正常退出。

最终运行日志没有取消监听器累积警告或显性应用错误。结构化证据见[验收记录](v1.7.0-验收记录.json)，界面截图见 README。
