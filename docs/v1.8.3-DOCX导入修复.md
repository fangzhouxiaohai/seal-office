# 1.8.3 DOCX 导入修复与 PDF 文字层兼容

本版延续 1.8.2 的 DOCX 导入修复，处理用户提交的《统计上大中小微型企业划分办法.docx》在打开时提示“内容可能未完整导入”的问题；同时修复本批新增的 PDF 文字层在 Electron 25 上无法取字、导致 PDF 预览失败的问题。

## DOCX 导入修复

- 段落标记里的 `w:spacing`（字间距，字符属性）不再被误判为“段落间距未完整导入”；字间距按 `letter-spacing` 导入，保存时写回 `characterSpacing`。
- 表格横向合并（`w:gridSpan`）与纵向合并（`w:vMerge`）按 `colspan`、`rowspan` 导入；被合并覆盖的续格不再重复输出。保存时按合并关系重建网格，写回 `w:gridSpan` 与 `w:vMerge restart/continue`，合并结构可以往返。
- 页脚页码域（`PAGE`、`NUMPAGES`，含 `w:fldSimple` 写法）保留为可更新的域：编辑器显示为占位，保存时写回真正的域代码，Word 打开后仍会自动重算页码，域内缓存结果保留原字符格式。
- 只有真正生效的首页或奇偶页页眉页脚（`w:titlePg`、`w:evenAndOddHeaders`）内容不同时才提示未导入；未启用时忽略对应版本，不再误报。
- 行内标签包裹的空格（如页脚“－ 3 －”）不再在保存时丢失。

## PDF 文字层兼容

`pdfjs` 6 的 `getTextContent` 用 `for await` 遍历文本流，而 Electron 25 使用的 Chromium 114 还没有 `ReadableStream` 的异步迭代接口，打开任意 PDF 都会提示“PDF 预览失败：… is not async iterable”，文字层与“复制文字／复制全文”不可用。本版在阅读器主线程与工作线程按 `getReader` 补出等价接口（`renderer/src/pdf/pdfStreamCompat.ts`），与既有的 `Promise.withResolvers` 兼容层同一处理方式。

## 同批改动

- 打印入口统一改为打印预览：文字、表格、演示先取打印用 PDF 再预览，确认后交给系统打印；PDF 工作台同样走预览。
- PDF 工具新增插入空白页、插入其他文件页面，以及页面编辑（插入 PNG/JPEG、矩形遮盖、文字／便签／替换文字）。
- 首页搜索扩展到最近文档正文内容：按文档名或内容过滤，并显示匹配片段。
- 支持把文件从资源管理器拖进窗口直接打开：可一次拖入多个，按扩展名分流并逐个打开；拖入过程中显示投放提示，不支持的格式与无法取得本机路径的内容通过固定弹窗如实说明。编辑区自己的投放区（幻灯片舞台接收图片等）优先，窗口级拖入不介入。
- 首页最近列表新增“批量管理”：可全选或逐条勾选，一次性移除多条最近记录；逐条写入持久化记录，部分失败时只移除成功的条目并列出未移除的原因。移除只影响最近列表，不删除磁盘文件。
- 新增[隐私声明](隐私声明.md)：按通行的隐私声明结构逐项说明开发者不收集数据、本机数据存放位置与加密情况、联网功能的外发范围（含屏幕录制与麦克风）、访问与删除方式；README 增加“隐私”小节，应用内帮助手册增加“隐私与数据在哪里”主题。
- 文字、表格、演示与 PDF 阅读支持 Ctrl（macOS 为 Command）+ 鼠标滚轮缩放页面内容：向上放大、向下缩小，触控板小增量先累积后走步，到达上下限停住；缩放只改变本机查看比例，不写入文档、不标记未保存，也不会让浏览器把整个界面一起缩放。帮助手册新增“缩放页面内容”主题。
- PDF 工具条的“复制文字／复制全文”改为图标按钮：这两个按钮此前受工具条 32×32 的定宽约束，中文标签被挤成两行；现在与翻页、缩放按钮一致显示为图标，文案保留在悬停提示与无障碍名称里，新增 `copy-text`、`copy-all` 两个图标。
- 缩放区间统一为 8.33%–6400%：文字、表格、演示、PDF 阅读共用同一套百分比档位（8.33%、12.5%、25%、33%、50%、66%、75%、90%、100%、110%、125%、150%、175%、200%、250%、300%、400%、500%、600%、800%、1000%、1200%、1600%、2000%、2400%、3200%、4000%、4800%、6400%），状态栏按钮与 Ctrl+滚轮都按档位行走；百分比文本对 8.33%、12.5% 这类档位保留两位并去掉末尾 0。PDF 在高倍下按 1600 万像素预算降采样渲染，再由 CSS 放大到目标尺寸，避免 6400% 时申请数亿像素的画布。
- 默认程序改为确认式自动设置：不再只跳系统页面。开关打开时启动检查，发现不是默认程序就弹确认框（“是否把海豹办公设为默认程序？”），点“立即设为默认”直接执行自动设置——注册程序类型、把四种扩展名的默认 ProgID 指向本程序、清除阻止生效的 `UserChoice`，并调用 `IApplicationAssociationRegistration::SetAppAsDefault` 请资源管理器写一次；随后用 `AssocQueryString` 回读真实结果。系统仍拦下时列出剩余格式，并一键打开海豹办公的系统默认应用页。
- **Windows 平台限制（本机实测）**：Windows 10 1809 之后，尤其 Windows 11，不再允许程序静默修改默认程序。实测结果：`.docx/.xlsx/.pptx` 调用系统接口返回 `0x80070483`（没有可用的关联），`.pdf` 返回 `0` 但并未真正改写；清除 `UserChoice` 后 Windows 会重新写回原来的处理程序（本机为 WPS），`HKCU\Software\Classes\.<ext>` 已指向 `SealOffice.<ext>` 也不影响系统按自己的记录解析。因此本程序的诚实行为是“检查 → 确认 → 尽力自动设置 → 必要时引导一次系统页面确认”，与 WPS 在 Windows 11 上的表现一致（WPS 同样只能把你带到同一个系统页面）。未采用伪造 `UserChoice` 哈希的做法：该机制未公开，写错会让对应扩展名进入“没有默认程序”状态，且可能被系统或安全软件重置。
- 四类文件新增选区浮窗与更丰富的右键菜单：文字里选中一段文字、表格里拖选多格、幻灯片里点选文本框或对象、PDF 阅读区选中文字后，编辑区上方自动浮出操作面板（`components/SelectionFloatPanel.tsx`）。面板不抢焦点（`mousedown` 阻止默认，选区保持不变）、随滚动/窗口变化或 Esc 收起、按选区矩形定位并在上方放不下时自动翻到下方。动作全部接到真实功能：文字为复制/剪切/格式刷/加粗/斜体/下划线/删除线/突出显示/字体颜色/清除格式/项目符号/编号；表格为复制/剪切/字体与填充/对齐/合并居中/自动换行/求和/清除内容；演示为复制/剪切/粘贴/删除对象/置于顶层与底层/对齐以及文本格式；PDF 为复制选中文字、翻译、解释、总结、问答。AI 快捷动作（润色、扩写、缩写、重写、更正式、更学术、更口语、翻译、解释、总结、续写、问答）统一经 `assistant/quickActions.ts` 派发 `seal-assistant-ask` 事件交给现有助手对话，按“预览确认后写回”处理，选区文本随指令一并给出。右键菜单同步补齐：新增 `role="menu"`、`menuitem`、`group`、`separator` 无障碍语义（快捷键提示不再进入无障碍名称），文字加突出显示与字体颜色调色板、清除格式与 AI 分组，表格加填充与字体颜色、数据分组（求和/清除内容/排序/筛选/删除重复项），演示加字体颜色与 AI 分组，PDF 阅读区新增复制选中文字、复制本页文字、复制全文文字与 AI 分组。演示的对象操作同时接受“多选对象”与“正在编辑的文本框”，右键与浮窗行为一致。

![PDF 工具条的图标按钮](screenshots/v1.8.3/pdf-toolbar-icons.png)
- 关闭确认弹窗改为“取消／保存后退出／不保存退出”三个选择，并整体缩小：新增的“保存后退出”按类型把每个未保存文档写回原路径（没有路径的先询问保存位置），全部成功才退出；任一个失败或用户取消选择位置时保留窗口并列出具体原因。弹窗宽度由 520 收到 432、高度按内容实测收缩，内边距与字号同步收紧，不再出现大片空白。演示文稿的保存模型抽取为 `ppt/saveModel.ts`，保存、另存为与退出前保存共用同一份映射。

## 保真边界

- DOCX：真正启用首页或奇偶页页眉页脚且内容不同的文档、页码之外的域代码与制表符、表格内的嵌套表格、浮动或经过裁剪旋转的图片、脚注尾注、批注、修订、超链接目标、多分节与精确分页仍会产生针对性警告。页码域显示的文字取自文件里上次计算的结果，Word 打开后才更新为实际页码。其他 Office 格式与上述未覆盖对象仍需用具体样例逐项验证，不能把没有警告等同于与 Word/WPS 完全一致。
- PDF：文字层按坐标叠加，只用于选择与复制，不改变页面原有的字符排布；扫描件没有文字层，因此没有可复制的文字。
