## 本次改动和成品

- 软件右上角新增全局“简体中文 / English”切换；选择会保存到本机，重启后继续使用。首页、新建弹窗、设置、编辑器菜单、公共提示和组件语言会同步切换；文字文档的“开始、插入、页面布局、引用、审阅、视图”六个功能区及其按钮、分组、下拉选项均已补齐英文。用户文档正文、表格数据、幻灯片内容和自定义文件名始终保持原文。

- 输入区左下角增加“收起智能助手”图标按钮；点击后关闭当前抽屉，后台状态与原关闭动作一致。
- Windows 桌面版增加 Access 数据库工作区：直接读写 Access 2003 MDB，以及 Access 2007、2010、2013、2016、2019、2021、2024 / Microsoft 365 ACCDB；支持结构浏览、数据查询与编辑、参数化增删改、表与索引查看、关系查看、SQL、CSV 导入导出和新建 ACCDB。修复 PowerShell 工作脚本超过 Windows 命令行长度上限，以及 `Data Source` 键被错误序列化导致已安装运行环境仍无法创建或重开的问题。

- 桌面版和移动资源版本统一提升到 1.9.15；Android 正式 APK 已由 HBuilderX 云打包生成并完成发布前验包。

### Access 支持边界

- 兼容范围按微软当前仍有直接迁移路径的格式收敛为 Access 2003 至今：2003 使用 `.mdb`，2007 及以后默认使用 `.accdb`。微软说明 `.accdb` 从 Access 2007 引入，当前 Access 仍可正常打开 Access 2002–2003 / 2000 MDB；本程序只承诺从 2003 起，避免把更早 Jet 格式误列为已验证能力。参考[微软 Access 文件格式说明](https://support.microsoft.com/en-us/access/which-access-file-format-should-i-use)和[转换为 ACCDB 的官方步骤](https://support.microsoft.com/en-us/access/convert-a-database-to-the-accdb-file-format)。
- 数据库操作通过微软 ACE OLE DB；缺少驱动时，界面会引导安装[Microsoft 365 Access Runtime](https://support.microsoft.com/zh-cn/access/download-and-install-microsoft-365-access-runtime)，并自动匹配 32/64 位驱动。旧式 Access 2003 MDB 还会在 32 位环境回退 Jet 4.0；界面提供数据库密码及可选 MDW 工作组文件、用户名和用户密码，兼容仍在使用 Access 2003 用户级安全的文件。微软对这类旧式安全机制的当前说明见[Access 2003 用户级安全](https://support.microsoft.com/en-us/access/set-or-change-access-2003-user-level-security-in-current-access-versions)。
- 当前实现覆盖表数据和可由 OLE DB 公开的结构、索引、保存查询及关系；不会执行或编辑 VBA、宏、ActiveX、窗体、报表、模块、数据宏、附件内部内容，也不承诺复制、用户级安全和 Access 专属 UI 行为。它是数据库工作区，不是 Microsoft Access 运行时界面的复刻。
- Access 2002/XP 及更早 MDB 不直接支持。若打开失败，原文件不会被覆盖；应先在 Microsoft Access 中确认文件正常并转换为 Access 2003 MDB 或 ACCDB。微软也说明 Access 2.0/95 等格式需要旧版 Access 作为中间转换工具，见[旧格式迁移说明](https://support.microsoft.com/en-us/access/import-access-2-0-and-access-95-databases-into-current-versions)。
- Access 功能只在 Windows 桌面版启用；Ubuntu 和移动端显示说明但不提供编辑。当前 Windows 构建机已安装 64 位 Microsoft 365 Access Runtime，并使用最终 `app.asar` 内的代码真实检测到 ACE 16.0/12.0，成功创建带中文与符号路径的 172,032 字节 ACCDB，确认文件头为 `Standard ACE DB`，随后重新打开并读取空表、查询与关系结构。Access 2003 MDB 的兼容路径由自动化覆盖，公开发布前仍建议使用实际历史 MDB 样本补做读写验收。

## HarmonyOS 上架要求

推荐按 HarmonyOS NEXT 原生应用准备，而不是把 Android APK 当作鸿蒙安装包。标准交付物是经签名的 App Pack（`.app`），其中包含 HAP/HSP 和 `pack.info`；相关定义见[华为 App Pack 术语](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/application-package-glossary)。

提交前通常需要：

1. 注册并完成华为开发者个人或企业实名认证；创建应用、确定不可随意更换的包名和签名体系。
2. 用 DevEco Studio/HarmonyOS SDK 或受支持的 DCloud 鸿蒙原生工具链生成 release 包，配置发布证书和 Profile，并通过兼容性、安全、稳定性及隐私自检。华为提供了[开发与签名入门](https://developer.huawei.com/consumer/cn/develop-novice-guide/)和[应用发布流程](https://developer.huawei.com/consumer/cn/app/submit/)。
3. 在 AppGallery Connect 填写中英文名称、简介、图标、截图、隐私政策、服务与支持联系方式、内容分级、测试账号和审核说明，上传已签名 `.app`。
4. 中国大陆分发需要 APP 备案；涉及网站/在线服务时核对 ICP，涉及新闻、出版、医疗、金融、教育、游戏等类目时提交对应许可。软著在华为现行总表中不是基础必选项，但类目或权利证明审核仍可能要求补充材料。完整入口见[AppGallery Connect 分发指南](https://developer.huawei.com/consumer/cn/appgallery/devstart/)和[应用资质要求](https://developer.huawei.com/consumer/cn/doc/80301)。
5. 海豹办公含智能助手。如果由运营方在中国境内向公众提供生成式 AI 服务，应额外核对生成式 AI 内容标识、算法备案、安全评估以及模型/服务商协议，并在审核说明中交代第三方 AI 服务、数据去向和关闭方式。

本次已由 HBuilderX 生成 HarmonyOS Release App Pack，并使用华为发布证书及 AppGallery Release Profile 完成正式签名。SDK 验签确认华为证书链、Profile 和 SHA-256 包摘要有效；SDK 扫描器检查通过。包名为 `com.sealoffice.mobile`，版本为 `1.9.15 (10915)`，兼容 API 13、目标 API 26，只声明 `ohos.permission.INTERNET`。正式包位于 `release/v1.9.15/海豹办公HarmonyOS1.9.15.app`。提交审核前仍应完成 HarmonyOS 真机安装、启动、文件导入导出和中英文切换验收。

## iOS 如何打包

对当前 uni-app x/DCloud 项目，按成本从低到高有三条路径：

1. **HBuilderX 云打包（最省事）**：运行 `npm --prefix mobile run build:ios` 准备本地编辑器资源，然后在 HBuilderX 选择“发行 → App-iOS 云打包”，填写 Bundle ID、Apple Distribution 证书及私钥、App Store provisioning profile，生成正式 IPA。DCloud 的[云打包说明](https://doc.dcloud.net.cn/uni-app-x/tutorial/app-package.html)列出了所需证书；正式上架不要使用自定义调试基座，见其[App Store 注意事项](https://doc.dcloud.net.cn/uni-app-x/tutorial/ios-app-store.html)。云打包可以省掉本地 Mac 编译机，但不能省掉 Apple 开发者身份和签名材料。
2. **Mac + Xcode 本地原生工程**：从 HBuilderX 导出本地资源/原生工程，在 macOS 用 Xcode 归档、签名、真机调试并上传，适合增加原生插件、定位审核问题和持续维护。DCloud 当前本地 SDK 要求最低 iOS 15，见[iOS 本地打包](https://doc.dcloud.net.cn/uni-app-x/native/use/ios.html)。
3. **macOS CI/Xcode Cloud**：原生工程稳定后，可用 GitHub Actions 的 macOS runner、Codemagic、Bitrise 或 Xcode Cloud 自动归档和上传；仍需要证书或 App Store Connect API Key，并承担相应 CI 成本。

个人 Apple ID 可以用 Xcode 做有限期真机调试，但不能上架。App Store/TestFlight 需要加入 [Apple Developer Program](https://developer.apple.com/programs/)（通常 99 美元/年）；公司主体还要有合法实体和 D‑U‑N‑S 编号，见[Apple 的 D‑U‑N‑S 要求](https://developer.apple.com/help/account/membership/D-U-N-S/)。Enterprise Program 只允许企业内部员工分发，不能拿来公开发布。

截至本说明日期，Apple 已自 2026-04-28 起要求提交包使用 Xcode 26 或更高版本并基于 iOS 26 SDK 构建，见[Apple 即将实施的提交要求](https://developer.apple.com/news/upcoming-requirements/?id=04282026a)。DCloud 云打包环境也必须选满足该门槛的版本；它当前公开的环境说明见[uni-app x iOS 编译环境](https://doc.dcloud.net.cn/uni-app-x/tutorial/app-env.html)。

正式上架还需要完成：

- App Store Connect 建档、唯一 Bundle ID、版本/构建号、价格和分发地区；上传可通过 Xcode、Transporter、Xcode Cloud 或 App Store Connect API，见[上传构建版本](https://developer.apple.com/help/app-store-connect/manage-builds/upload-builds)。
- 应用名称/副标题/关键词/描述、1024×1024 图标、各设备截图、支持 URL、隐私政策 URL、年龄分级和出口合规；填写 [App Privacy](https://developer.apple.com/help/app-store-connect/manage-app-information/manage-app-privacy) 数据收集与跟踪声明。
- 提供可用的审核账号、测试路径和审核备注；明确智能助手使用的外部 AI 服务、登录方式、联网能力、用户内容如何传输和删除。见[App Review 审核信息要求](https://developer.apple.com/help/app-review/before-submitting-for-review/complete-review/)。
- 检查第三方 SDK 的隐私清单和签名要求，见[常用第三方 SDK 要求](https://developer.apple.com/support/third-party-SDK-requirements/)。
- 如果在中国大陆区上架并提供互联网信息服务，按实际业务准备 ICP 备案；游戏、图书、新闻、宗教等类目另有许可/版号字段，见[App Store Connect 应用信息要求](https://developer.apple.com/help/app-store-connect/reference/app-information/app-information/)。

当前仓库的 `build:ios` 明确只生成共用 WebView 资源，不会直接产生 IPA。因此最短可行路线是：准备 Apple Developer Program 账号和正式证书/Profile → 用当前版 HBuilderX 云打包生成 release IPA → TestFlight 内测 → 修正权限、隐私与审核账号材料 → App Store Connect 提审。

## HBuilderX 云打包 IPA 所需证书从哪里取得

证书来自 [Apple Developer](https://developer.apple.com/account/)，不是从 DCloud/HBuilderX 购买，也不应向第三方购买或借用：

1. 使用账户持有人的 Apple Account 加入 [Apple Developer Program](https://developer.apple.com/programs/)，完成实名与年费；免费 Apple 账户只能做有限的本机真机调试，不能提交 App Store。
2. 在 Certificates, Identifiers & Profiles 注册显式 App ID，Bundle ID 使用 `com.sealoffice.mobile`，并确保与 HBuilderX `manifest.json` 一致。
3. 在持有私钥的电脑上生成 CSR，在 Apple 后台创建 **Apple Distribution** 证书并下载 `.cer`。把证书与对应私钥一起导出为带密码的 `.p12`；仅有 `.cer` 没有私钥，HBuilderX 无法签名。Apple 官方证书类型说明见[Certificates overview](https://developer.apple.com/help/account/create-certificates/certificates-overview)。
4. 在 Profiles 中创建 **App Store Connect** 分发描述文件，选择同一个 App ID 和 Distribution 证书，下载 `.mobileprovision`。官方步骤见[创建 App Store Connect provisioning profile](https://developer.apple.com/help/account/provisioning-profiles/create-an-app-store-provisioning-profile)。
5. HBuilderX“发行 → App-Android/iOS-云打包 → iOS”中依次选择 `.p12`、填写其私钥密码、选择 `.mobileprovision`，生成正式 IPA。DCloud 官方对应字段见[uni-app x 云打包](https://doc.dcloud.net.cn/uni-app-x/tutorial/app-package.html)。

`.p12` 和密码等同于发布签名权限，应离线加密备份，不发到聊天、代码仓库或网盘公开链接。HBuilderX 云打包用的 `.p12` 密码可以单独设置，不建议与商店登录密码共用。证书和 Profile 通常由 Apple Developer Program 的 Account Holder 或 Admin 创建；如果以后更换证书，需要同步重新生成 Profile 和 HBuilderX 配置。
