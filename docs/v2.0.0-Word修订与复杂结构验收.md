# 2.0.0 Word 修订与复杂结构验收

本报告记录第二轮文字引擎实现的实际范围。原生 WPS 分析证据仍见 [WPS 文字引擎观察](v2.0.0-WPS文字引擎观察.md)；其中早期兼容缺口是当时状态，下面的已验证实现取代其对应的应用状态描述。没有把 WPS 反编译代码、程序资源或第三方文档内容引入产品，也没有据少量函数分析宣称已还原 WPS 全部行为。

## 修订记录、显示与审阅

有效、安全的 DOCX 来源包在编辑模型中作为独立、不可直接编辑的元数据保留；正文使用稳定块映射。普通正文的修改实际覆盖对应正文节点，未修改部件保留原生 XML、关系和资源。保存后重新解析所得内容必须包含真实编辑，不能以复制原文件替代保存。

| 功能 | 已实现和验证 | 明确边界 |
| --- | --- | --- |
| 插入、删除 | 键盘输入、单段及跨段文字删除/替换、Enter 段落边界、中文 IME 最终词、字素删除记录作者、时间、ID；写回原生 `w:ins`/`w:del` 和 `w:delText` | 不等于所有编辑操作都会生成原生修订；新建表格/单元格结构、所有段落属性修改尚无完整追踪 |
| 粘贴、剪切 | 原生粘贴与工具栏插入统一进入追踪替换；行内富文本同时保留原文删除历史和新文格式；剪切删除沿用相同历史路径 | 修订模式下块级结构粘贴和拖放明确保护原文并提示，尚不支持完整结构修订 |
| 字符格式 | 选择文字后通过现有常用字符格式命令生成 `rPrChange`，保留先前格式；原生历史格式不会混入当前显示 | 当前覆盖加粗、倾斜、下划线、删除线、字号、字体、颜色、上下标等命令；不承诺全部格式命令均自动追踪 |
| 审阅操作 | 逐条、全部接受/拒绝；原生来源经过真实 DOCX 写回与读取后更新界面；可撤销本机审阅操作 | 下列未支持的结构修订不会假成功；接受全部遇到它们会明确失败并保留当前内容 |
| 原生移动 | 保留来源/目的、段落移动和命名范围关系；关联来源/目的共同接受或拒绝；不同时冒充最终正文显示两份内容 | 复杂跨结构移动的全部组合未穷尽验证 |
| 原生属性历史 | `rPrChange`、`pPrChange`、`sectPrChange`、`tblPrChange`、`tblPrExChange`、`trPrChange`、`tcPrChange` 可保留；接受移除历史、拒绝恢复完整旧属性节点 | 涉及这些历史的原生保护块不能直接任意改写；先审阅或在兼容引擎中处理 |
| 表格历史 | 原生行插入/删除有可视标记并可接受/拒绝；未支持单元格历史及网格变化保留在来源包中 | `cellIns`、`cellDel`、`cellMerge`、`tblGridChange`、部分 `customXml` 范围及 `tcPr` 下结构插删目前只保留，接受/拒绝明确拒绝执行 |
| 修订显示 | 全部标记、最终正文、原始正文切换不改历史数据；原始视图只读；列表显示作者、时间和部件 | 浏览器修订显示与 WPS 气泡、版式、打印修订标记不保证逐像素相同 |

段落标记、行插删和历史属性的处理依照本项目独立 OOXML 样例与 [Microsoft Open XML 修订说明](https://learn.microsoft.com/en-us/office/open-xml/word/how-to-accept-all-revisions-in-a-word-processing-document)核对。拒绝属性修订时恢复的是历史属性集合；删除段落标记涉及段落边界，不把它当作普通可见字符。

修订 ID 使用合法范围内未占用值，兼顾原生 ID 已达 `2147483647`、仅存在页眉/脚注等源包目录的历史记录；不改写来源 ID，也不把全部 ID 展开为函数参数。

## 复杂文档、可视呈现与编辑保护

| 内容 | 往返与渲染 | 直接编辑能力 |
| --- | --- | --- |
| 多节、横竖混排、不同纸张/边距、分栏、奇偶起节 | 原生节 XML 和继承关系保留；HTML 包含分节布局元数据供浏览器测量；真实 DOCX→PDF 用原生兼容引擎排版 | 浏览器不是完整原生逐页布局引擎。多节文档的全局纸张修改会明确保护，尚无完整逐节属性编辑 UI |
| 默认、首页、偶数页页眉页脚 | 原生部件与引用保留，节元数据包含继承后的内容；PDF 真实可见；普通默认页眉/页脚修改能写入并重开 | 首页/偶数页的独立 UI 编辑及所有复杂页眉绘图不完整；高级结构只读保护 |
| 脚注、尾注 | 原生引用、注释内容与关系保留；普通注释正文修改写入，PDF 中实际显示脚注 | 高级注释对象受保护；浏览器注释排版位置不承诺与原生引擎完全一致 |
| 锚定绘图、VML、裁剪/效果及其他复杂对象 | 原始节点、关系、资源保留；可识别图片在 HTML 可见，完整对象通过原生 PDF 可视预览/打印；无法解释的对象有保护提示 | 这些来源块只读，当前不支持锚定图片位置、大小、绕排等任意编辑；没有把无损保留冒充完整对象编辑 |
| 简单行内图片 | 继续使用原有可编辑图像模型；图片资源和新编辑均真实写出 | 原有宽高、旋转、翻转等已有能力保持；复杂原生绘图不因此成为可编辑对象 |
| 域、批注及扩展结构 | 动态 PAGE/NUMPAGES 支持原生写回；高级源包中的其他原始域/扩展部件保留；不支持完整编辑时保护相关块/提示 | 其他域不承诺本地计算或刷新；原生批注完整交互仍非本轮已完成范围 |

打印预览、导出 PDF、另存为 PDF 共用同一当前模型 PDF 缓存，并在转换前明确选链：普通文字、简单行内图片和普通脚注尾注保留原有离线 HTML/pdfmake 路径，不要求登录；复杂保护块、多节/分栏、首页或偶数页独立页眉页脚、原生修订及域等使用当前模型→真实 DOCX→兼容引擎 PDF。复杂链路失败时不会降级为 HTML。移动端/Web 使用已登录账号网关时仍逐次确认上传正文。浏览器测量页数用于编辑视图导航；复杂文档最终 PDF 以兼容引擎实际排版为准。

## 协作和来源保护

Word 实时协作接入共享/团队文件绑定，普通本机文件维持本机编辑。每笔输入发布草稿；远端更新不推入本机编辑历史；IME 期间保留稳定基线和本地草稿，完成后与远端合并。协作撤销仅撤本机操作。来源包与正文分开存储，不能字符级混合 base64；并发替换不同来源包由协作层明确报冲突，保留本机模型。

保存前刷新当前 DOM 和协作草稿；在线先同步，离线允许本机保存且提示修改待同步。共享直接下载的物化由协作模块复用 `joinWordModel→htmlToDocxModel→writeDocx`，保持来源结构。

来源包限压缩 20 MiB、展开 100 MiB、单部件 20 MiB、2000 部件。拒绝路径穿越、宏、ActiveX、嵌入执行内容、外部自动加载资源、危险关系和 XML DTD/实体；允许普通安全外部超链接。来源块删除、伪造或高级块修改无法可靠合并时明确失败，不能静默写出缺失结构的文件。DOCM 宏不会因另存 DOCX 被带入。不能安全保留的旧片段/危险源内容继续使用现有保真警告及来源覆盖保护。

所有夹具为本项目独立生成。主进程七个相关文件 139 项通过；编辑器既有 UI/导出/兼容等六文件 96 项通过；修订/源包核心五文件 32 项通过。收尾补丁再次执行实际 DocEditor 修订三项（含真实 HTTP 双账号并发、长 IME、仅撤销本机、真实 DOCX 导出），以及输入修订六项；均通过。TypeScript 无错误。最终全仓回归和发布构建由主发布流程另行执行，不能把局部通过写成全仓通过。

关键测试文件：

- `main/office/docxRevisionHistory.test.js`、`docxSourceSecurity.test.js`、`docxCompatibilityBoundary.test.js`：原生 XML、关系、命名空间、安全限制与明确不支持的结构动作。
- `renderer/src/editor/docxSource.test.ts`：正文真修改后保留原始复杂结构；默认页眉/脚注真修改；受保护块修改/移除拒绝；格式历史恢复；命名移动两端；表格行历史；反复六次重开不复制资源和样式；删除普通源块不复活。
- `renderer/src/editor/trackedEditing.test.ts`、`trackedFormatting.test.ts`、`docxRevisionHistory.test.ts`、`DocEditor.revisions.test.tsx`：真实输入和 UI→模型→DOCX→重开的闭环。
- `mobile/tests/revision-browser-actions.cjs`：真实生产完整 App、实际 codec、修订作者/显示/保存重开、CtrlHome 排除隐藏来源包，以及 360/390/820px 窄屏布局。私有独立构建隔离于正式生成资源；报告 `.upgrade-private/word-browser-final/verification.json`，截图 `screenshots/mobile-word-revisions.png`。

原生复杂夹具：`.upgrade-private/word-v200-final/complex-sections.docx` 与真实修改后的 `complex-sections-saved.docx`。兼容引擎分别生成五个物理页面，包含强制保留的奇数起节自动空白页。两版共十页均已渲染并逐页检查：原版“原始甲”与新版“已修改乙”、蓝橙双色锚定图、脚注、首页/继承偶数/默认页眉、双栏、横竖页、物理第4页空白和第5页页脚5均通过。结构与视觉证据为 `.upgrade-private/office-pdf-third-pass/verification.json`、`visual-verification.json` 及两版 contact sheet。

本轮实现提供完整来源历史保留、受支持修订的真实审阅和复杂结构渲染保护；未证明所有原生修订组合、绘图对象和分页属性都能直接编辑，不能称为全部 WPS 功能一比一完成。
## 离线 PDF 回归修正

收尾发现普通文档被无条件送往原生转换，破坏未登录/离线打印。新增 `DocEditor.pdf.test.tsx` 先得到两项明确失败（普通预览与另存 PDF），再按文档结构显式选链后，三项实际 UI 测试全部通过。`wordPdf.test.ts` 追加四项真实 DOCX 读取策略样例，证明单节首页/偶数页页眉、PAGE 域和原生修订仍必须原生转换，不能仅按是否多节判断。TypeScript 再次通过。

使用最新私有完整生产 App，原 `mobile/tests/harmony-review.cjs` 仅替换 bundle/font/output 路径，未改断言，原有十组宿主流程全部通过，包括实际中文打印、系统 print、导出 PDF 并打开、脚注尾注和保存确认。报告为 `.upgrade-private/word-offline-pdf-final/harmony/harmony-browser-review.json`。

追加生产验收实际打开普通 DOCX，包含独立创作蓝橙行内图片、脚注和尾注；离线预览与导出复用同一 PDF，兼容引擎调用数为零。PDF 文字层确认正文和两类注释，截图确认蓝橙图片可见。同一生产 App 再打开复杂原生夹具，兼容引擎不可用时打印与导出明确失败，HTML 转换次数未增加。报告 `.upgrade-private/word-offline-pdf-final/verification.json` 中 `errors`、`blocked` 均为空；实际 PDF 和截图在 `screenshots/offline-image-notes.pdf`、`screenshots/offline-image-notes.png`。
