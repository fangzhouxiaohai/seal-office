## 回滚

部署脚本在健康检查失败时会恢复原 `current` 指针及原工作进程应用，并共同重启两个服务；本次没有触发回滚。新数据库保持增量迁移，不能仅恢复旧 SQLite 而保留一部分新对象。

手工回滚时应先停止两个服务，将 `current` 切回上一版本，恢复备份里的 `worker-app`，共同恢复服务，并保留新数据目录、协作表和团队对象。旧版本不提供新协作功能，客户端会明确报告能力缺失；回滚期间暂停协作写入及清空云空间操作。如需恢复部署前的数据状态，先完整另存升级后目录，再在停机期间恢复整份一致备份。

协作实现的明确边界见 `server/COLLABORATION.md`：团队权限作用于整个团队，没有文件夹级 ACL 或实时 CRDT；撤销无法收回用户已经下载并解密的副本；团队回收站界面尚未提供。
