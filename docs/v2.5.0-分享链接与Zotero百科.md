# 分享链接与 Zotero 百科（2.5.0）

## 一、鸿蒙 / Android 云盘「接口不存在」修复

### 现象
鸿蒙（以及受同一桥接影响的 Android）云盘中，重命名文件和移动到文件夹都弹出「接口不存在」，实际上什么都没改。

### 根因
`mobile/pages/workspace/workspace.uvue` 的原生请求桥接只能表达 GET / POST / PUT / DELETE：

```
let requestMethod = http.RequestMethod.GET
if (method == 'POST') ... else if (method == 'PUT') ... else if (method == 'DELETE') ...
```

`@ohos.net.http` 与 `uni.request` 都没有 PATCH 常量，于是 `PATCH /v1/nodes/:id` 被降级成 **GET**。服务端路由按方法匹配，没有 `GET /v1/nodes/:id`，于是落到兜底分支返回 404「接口不存在」。

受影响的不止重命名与移动：标签改名、团队改名、团队成员改角色、设备改名、团队文件改名与移动全部走 PATCH，这些在移动端同样是坏的。

### 修复
1. `mobile/native/workspace.uts` 新增 `transportMethod()` 与 `methodOverrideHeaders()`：PATCH 在传输层改发 POST，并附带 `X-Seal-Method-Override: PATCH`。
2. `mobile/pages/workspace/workspace.uvue` 统一走这两个函数，Android 与鸿蒙两条分支都生效。
3. `server/index.cjs` 新增 `effectiveMethod()`：只接受 `PATCH` 这一种覆盖值，其余一律忽略，避免被用来绕过方法限制。`/v1/capabilities` 增加 `methodOverride: 1` 供客户端探测。

### 验收
`server/test/shareLinks.test.cjs` 覆盖：POST + 覆盖头可完成重命名与移动；`X-Seal-Method-Override: DELETE` 不会被接受。

## 二、云空间分享链接

### 定位
与既有「文档共享」是**两条互不相干的通道**：

| | 文档共享 | 分享链接 |
|---|---|---|
| 接收人 | 必须注册并开通云空间 | 任何拿到链接的人 |
| 入口 | 应用内 | 浏览器落地页 |
| 登录 | 需要 | 不需要 |
| 权限 | 只读 / 可编辑 | 只读下载 |

### 能力
- 有效期：1 天 / 3 天 / 7 天 / 30 天 / 永久
- 访问码：可不设，或设 4–8 位数字
- 落地页有文件信息与下载按钮，点击即在浏览器内解密并保存

### 零知识设计
私有文件是客户端 AES-256-GCM 加密的，服务器没有密钥。因此：

- **文件密钥、文件名、节点标识都放在 URL 的 `#` 片段里**。浏览器不会把片段发送给服务器，所以即使整库泄露也无法解密、也看不到文件名。
- 设了访问码时，片段里放的是「用 PBKDF2(访问码) 派生密钥包裹后的文件密钥」，访问码本身不进链接、不落库。
- 服务端只保存 `access_hash`（链接凭证摘要）与 `code_digest`（访问码 scrypt 摘要），并且对访问码按 IP 限次（15 分钟内 8 次），挡住在线枚举。
- 客户端（`main/cloud/shareLink.js`）、移动端 shim（`mobile/web/shims/crypto.js`）、落地页（`share/index.html`）三处 PBKDF2 参数必须一致：
  `PBKDF2-SHA256(访问码, 'seal-share-link:' + 链接标识, 100000 次, 32 字节)`。
  一致性由 `mobile/tests/pbkdf2-parity.test.mjs` 守住。

### 接口
| 方法 | 路径 | 鉴权 | 用途 |
|---|---|---|---|
| POST | `/v1/share-links` | 登录 | 生成链接 |
| GET | `/v1/share-links` | 登录 | 我的链接列表 |
| DELETE | `/v1/share-links/:id` | 登录 | 取消链接 |
| GET | `/v1/share-links/:id` | 匿名 | 落地页信息 |
| POST | `/v1/share-links/:id/verify` | 匿名 | 校验访问码 |
| GET | `/v1/share-links/:id/content` | 匿名 + 链接凭证 | 下载密文 |

文件进回收站、被彻底删除、或账号清空云空间时，相关链接自动失效。

### 部署要求

1. **服务端**：升级到含 `server/shareLinks.cjs` 的版本并重启。数据库表 `share_links` 会自动创建，无需手工迁移。
2. **落地页**：把仓库根目录的 `share/` 上传到站点根，并确保 `/share/` 与 `/api/` 同源。
3. **Nginx**：站点需要同时满足
   - `/share/` 返回静态页；
   - `/api/v1/share-links/` 反向代理到本服务；
   - 反向代理必须保留 `X-Seal-Method-Override` 请求头（默认会保留，不要手工删除自定义头）。

   参考配置：

   ```nginx
   location = /share { return 301 /share/; }
   location ^~ /share/ {
       alias /var/www/seal-office-web/share/;
       index index.html;
       add_header Cache-Control "no-cache" always;
       add_header X-Content-Type-Options nosniff always;
       add_header Referrer-Policy no-referrer always;
       add_header Content-Security-Policy "default-src 'self'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; connect-src 'self'; base-uri 'self'; form-action 'none'; frame-ancestors 'none'" always;
   }
   ```

   链接形如 `https://<站点>/share/#/s/<链接标识>?a=<凭证>&k=<片段>`。片段在 `#` 之后，不会出现在 Nginx 访问日志里。

4. **客户端**：`/v1/capabilities` 返回 `shareLink: 1` 才会显示「生成分享链接」。旧服务端不返回该字段时菜单入口不出现，不会产生误导。

### 已知边界
- 落地页依赖 WebCrypto，需要 HTTPS（或 localhost）。
- 单文件上限 100 MiB，与云端配额一致。
- 链接一旦外传无法收回，只能取消链接让后续访问失效；已下载的副本无法追回。

## 三、Zotero 百科接入

### 结论：并入知识库，不新建模块
Zotero 中文社区提供的是「按主题组织的 Markdown 文档」，与知识库的「检索 → 阅读 → 引用 → 提问」链路完全同构。单独开一个模块会重复实现读取、检索与引用，反而增加用户学习成本。因此在「海豹知识库」顶部加了资料源切换：

- **我的知识库**：原有私有 / 公开知识文件
- **Zotero 百科**：社区文档目录

在 Zotero 页签里点「引用并提问」，会把当前文章按标题切段送进知识库的问答链路，与自己的知识文件行为一致，并同样走 `requireAIIdentity` 与单次资料授权确认。

### 为什么必须走主进程代理
`zotero-chinese.com` **没有返回 `Access-Control-Allow-Origin`**，浏览器直连会被跨域策略拦截；移动端 `file://` 页面更拿不到原文。所以由 `main/cloud/zoteroDocs.js` 代理：

- 只允许访问 `zotero-chinese.com` 一个域名
- 只允许 GET，只放行 `llms.txt` 与 `.md` 原文
- 路径白名单拒绝 `..`、查询串、片段与超长输入，不是通用反向代理
- 24 小时本地缓存，减少对社区站点的请求

### 数据来源
- 目录：`https://zotero-chinese.com/llms.txt`（社区官方维护，实测 105 条）
- 正文：`https://zotero-chinese.com/<路由去斜杠>.md`

站点若调整目录格式，客户端会提示「资料目录格式已变化，请更新客户端」而不是展示空列表。

## 四、移动端 UI 优化

### 图标颜色
`renderer/src/components/iconLibrary.json` 里 89 个移动端图标把品牌紫 `#7363DB` 直接写死在 SVG 上。放在品牌色实心主按钮上几乎不可见——这就是「发送按钮像是一个空方块」的原因。

修复：移动端图标的 `stroke` 统一改为 `currentColor`（共 111 处），颜色交给所在容器决定；白色内嵌高光保持白色不变。

### 发送按钮
`send` 图标原本是 0.8 描边的空心细线三角，在 15 px 下模糊不清。改为实心纸飞机（双翼分层），提高辨识度，颜色仍由按钮决定。

### 长文字改图标
`renderer/src/components/RecentDocs.tsx` 的文档标题栏在窄屏把「批量管理」「按修改时间」「查看全部」收成图标按钮，保留 `aria-label` 与 `title`，可访问性不降级。

### 其它排版
- 分享链接弹窗、Zotero 百科页均为窄屏单列布局，按钮撑满，触控高度 ≥ 44 px。
- Zotero 正文表格在窄屏改为横向滚动，避免撑破卡片。
- 落地页针对 `prefers-color-scheme` 与 `safe-area-inset` 适配，支持深色模式与刘海屏。
