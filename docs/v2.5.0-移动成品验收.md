### 验签细节

- **App Pack**：`Find Hap Signing Block success, version: 3, block count: 2`，返回 `verify-app success`。
  该文件不含 codesign 块（`can not find codesign block`），这是 App Pack 的正常形态——它是外层容器，原生库的代码签名在内层 HAP 上校验。
- **HAP**：`block count: 3`，逐条校验 `libc++_shared.so`、`libdcloudlayout.so`、`libuni_modules__uni_crash_lib.so`、`libvideoCompressor.so`（arm64-v8a 与 x86_64），`verify codesign success`，profile 类型为 `release`，`verify permission sign success`。

### 安装方式

签名所用的 Profile 实测值：`type: release`、`app-distribution-type: app`，且**不含 `device-ids` 字段**。

这意味着它是一份面向 AppGallery 分发的发布型 Profile，不是按设备 UDID 限定的调试 Profile。因此：

- `.app`：上传 AppGallery 上架（含测试渠道分发）；
- `.hap`：可直接安装（`hdc install` 或 DevEco 运行），不受“必须预先登记设备 UDID”的限制。

早前版本的本文档曾写“HAP 只能装到已登记 UDID 的设备”，那是基于“只有 Release Profile”的推断，与实测 Profile 字段不符，已更正。
若后续改用调试专用 Profile（Profile 内含 `device-ids`），才需要把目标设备 UDID 预先登记进去。

## 五、Android

安卓走 DCloud 云端证书云打包（`mobile/scripts/pack.mjs`）。云打包结果以 HBuilderX 返回的下载地址为准；下载后必须执行

```bash
node mobile/scripts/apk-check.mjs <APK路径> --require-current --archive <归档目录>
```

校验版本号、包名、双 ABI、被移除的权限与签名指纹，通过后按 `seal-office-2.5.0-android.apk` 原字节归档。

**首次云打包失败**，错误来自 UTS 转 Kotlin 的编译错误：

```
index.kt:195:29 Argument type mismatch:
actual type is 'Function2<Any, String, Unit>',
but 'Function1<Map.Entry<String, Any?>, Unit>' was expected
```

根因：`methodOverrideHeaders` 里用了 `headers.toMap().forEach((value, key) => ...)`，UTS 编译到 Kotlin 后生成双参数 lambda，而 Kotlin 的 `Map.forEach` 需要单参数 `Map.Entry`。

修复：PATCH 语义改由 TypeScript 侧（`mobile/web/native.ts`）决定——在那里改方法、加 `X-Seal-Method-Override`、并给出头名列表；UTS 侧只保留 `copyHeaders(headers, names)` 做纯索引复制。用 `native-check.mjs` 实际跑 UTS → Kotlin 转换确认生成的代码是标准 `while` 循环，`toMap()` 已彻底消失，检查返回 0。

## 四、复现命令

```powershell
# 鸿蒙：构建 + 云打包 + 归档 + 验签
$env:DEVECO_STUDIO_HOME = "E:/DevEco Studio"
node mobile/scripts/pack-harmony.mjs

# 独立复验（不影响产物）
$j = "E:/DevEco Studio/jbr/bin/java.exe"
$t = "E:/DevEco Studio/sdk/default/openharmony/toolchains/lib/hap-sign-tool.jar"
& $j -jar $t verify-app -inFile release/v2.5.0/seal-office-2.5.0-harmony.app -outCertChain a.cer -outProfile a.p7b
& $j -jar $t verify-app -inFile release/v2.5.0/seal-office-2.5.0-harmony.hap -outCertChain h.cer -outProfile h.p7b
```

`verify-app` 要求显式给出 `-outCertChain` 与 `-outProfile`，缺参数会报 `11011008 Check param failed`；这是工具参数约束，不是签名问题。
