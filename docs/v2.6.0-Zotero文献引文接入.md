# 2.6.0 Zotero 文献引文接入

本文档记录 2.6.0 文献引文能力的实现方式、协议细节、许可要求与已知边界。

---

## 一、为什么这样接入

2.5.0 的做法是把 Zotero 中文社区的开源文档并入知识库，解决的是「查教程」。而用户要的是「像 Zotero 集成 Word 那样，在文档里插入引注并自动生成参考文献表」。

两者不是一回事：

| 维度 | 2.5.0 做法 | 正确做法 |
| --- | --- | --- |
| 对象 | 社区说明文档 | 用户文库里的文献条目 |
| 通道 | 抓 `zotero-chinese.com` 的 Markdown | 本机 Zotero 客户端 |
| 产物 | 知识库问答片段 | 文档中的引文域 + 书目域 |
| 能力 | 读文档、问问题 | 插引注、生成书目、换样式、刷新、取消链接 |

Zotero 集成字处理器的核心是**域代码 + CSL 引擎排版**，本地排版不依赖 Zotero 是否在运行。这决定了实现分三层：

1. **域代码层**：文档里存的是标准 `fldChar` 三段式域，指令为 `ITEM CSL_CITATION {...}` 与 `BIBL {...} CSL_BIBLIOGRAPHY`。
2. **本地排版层**：citeproc + CSL 样式 + locale 语言包在本地完成排版。
3. **协议层**：Local API（`http://127.0.0.1:23119`）读取本机文库。

前三层中第 1、2 层可完全离线验收，第 3 层需本机装有 Zotero。

## 二、实现结构

### 2.1 渲染层 `renderer/src/citation/`

| 文件 | 职责 |
| --- | --- |
| `types.ts` | CSL-JSON 条目模型、引文簇、渲染结果类型 |
| `styles.ts` | 六套内置样式与两个语言包，附来源与许可 |
| `engine.ts` | citeproc 封装：整篇重排 + 书目生成 |
| `fieldCode.ts` | `ITEM CSL_CITATION` / `BIBL` 域的序列化与解析 |
| `documentModel.ts` | 编辑区节点读写、刷新、取消链接 |
| `commands.ts` | 插入引文、插入书目、刷新全部域、取消链接 |
| `zoteroItemToCsl.ts` | Zotero 条目 → CSL-JSON 映射 |
| `zoteroNormalize.ts` | Zotero Local API 返回值归一化 |
| `文献库面板.tsx` | 四页签面板：文献库 / Zotero 文库 / 引文 / 样式 |
| `assets/styles/` | 六个 `.csl` 文件 |
| `assets/locales/` | `locales-zh-CN.xml`、`locales-en-US.xml` |

### 2.2 主进程

| 文件 | 职责 |
| --- | --- |
| `main/zotero/localApi.js` | Local API 只读客户端 |
| `main/ipc/zoteroChannel.js` | 动作白名单 IPC，与 `cloud.invoke` 隔离 |
| `main/office/docxCitationFields.js` | `fldChar` 三段式引文域读写 |

## 四、Local API 协议要点

### 4.1 端点

- 基址：`http://127.0.0.1:23119/api/`
- 条目列举：`/api/users/0/items/top?limit=N&format=json`
- CSL 导出：`?format=csljson`
- 书目渲染：`?format=bib&style=<样式标识>`

### 4.2 必须先在 Zotero 里开启

设置 → 高级 → 勾选「允许本机其他应用与 Zotero 通信」。未开启时 `/api/` 返回 `403 Forbidden`，响应体为 `Local API is not enabled`。

若该开关未被写入 `prefs.js`，需写入完整键名（注意前缀）：

```
extensions.zotero.httpServer.localAPI.enabled
```

写入后需重启 Zotero 生效。

### 4.3 一个必须处理的坑：`csljson` 的 `id` 是 URI

真机实测（Zotero 10.0.7）：`format=csljson` 返回的 `id` 是完整 URI

```
http://zotero.org/users/local/<库标识>/items/<条目键>
```

不是条目键本身。直接拿来当文档内 id 会导致同一文献从不同来源加入时被判为两条，回链也会写成 URI 而匹配不上。

`zoteroNormalize.ts` 的 `提取条目键()` 负责从 URI 中取出真实键（形如 `JUQ7C9NY`）。已用真机数据交叉核对：提取结果与 `format=json` 返回的 `key` 逐条一致。

### 4.4 一条协议层约束：所有 Zotero 请求必须走主进程

Zotero 的 HTTP 服务会判断请求是否来自浏览器：

```
isBrowser = (user-agent 以 "Mozilla/" 开头) || ('origin' in headers)
```

命中且端点未显式放行时直接掐断响应。渲染进程的 UA 是 Mozilla 系且带 Origin，因此**渲染进程里 `fetch('http://127.0.0.1:23119/...')` 必然失败**。

主进程侧固定使用 `User-Agent: SealOffice/2.6 (zotero-bridge)`，且不携带 `Origin`。

## 五、许可

| 组件 | 许可 | 处理方式 |
| --- | --- | --- |
| citeproc-js（npm `citeproc@2.4.63`） | CPAL-1.0 OR AGPL-1.0 | 采用 CPAL-1.0 分支，不改源码，随包附许可与署名 |
| CSL 样式（zotero-chinese/styles） | CC BY-SA 3.0 | 随包附 NOTICE，声明来源与许可 |
| locale（citation-style-language/locales） | CC BY-SA 3.0 | 同上 |

选 citeproc-js 而非其他实现的原因：中文社区样式（GB/T 7714-2015 等）依赖它的 CSL-M 扩展能力（双语「等 / et al」混排），换引擎会排错。

## 六、已知边界

1. **Citing Protocol 未实现**：在 Zotero 引文对话框内选题的完整协议（`/connector/document/execCommand` + `respond` 事务闭环）尚未接入。当前是在海豹办公自己的面板里选题。
2. **自定义 `.csl` 样式导入未实现**：目前只用六套内置样式。
3. **脚注 / 尾注形式的引文未实现**：目前只支持文内引文。
4. **「从未引用文献加入书目」无界面入口**：`BIBL` 的 `uncited` 字段已能读写，但界面未暴露。

## 七、真机验收记录

环境：Zotero 10.0.7，安装于 `E:\softs\Zotero`。

| 用例 | 结果 |
| --- | --- |
| `/connector/ping` | 200，`x-zotero-version: 10.0.7` |
| `/api/` | 200，含 `zotero-api-version: 3`、`zotero-server-id` |
| `/items/top?format=json` | 200，返回真实条目 |
| `/items/top?format=csljson` | 200，`id` 为 URI 形式 |
| 条目键归一化 | 提取结果与 `format=json` 的 `key` 完全一致 |
| `/items/top?format=bib&style=apa` | 200，书目 HTML 正常 |
| `/items/top?format=bib&style=china-national-standard-gb-t-7714-2015-numeric` | 200 |

真机比对中发现并修复了一个缺陷：`engine.ts` 的 `取书目正文` 原本只按无属性的 `<div class="csl-entry">` 剥壳，而 citeproc 实际输出带 `style` 属性且正文另包在 `<div class="csl-right-inline">` 里，导致书目正文残留块级 div。已改为按标签名剥除，并补 2 项回归测试。
