# Windows 语言切换闪退排查记录

## 现象和结论

2026 年 11 月 6 日，用户反馈 Windows 安装版首次切换语言时闪退。系统应用事件和本机进程转储记录到异常 `0xc000041d`。本次只读取了进程转储中与故障有关的调用栈、符号和无障碍节点结构，未读取或归档用户文档内容。

已定位到原生引擎的退出路径：Windows UI 自动化组件调用 Chromium 的 `BrowserAccessibilityComWin::get_hyperlink`，该方法发现缓存的超链接标识所指向的无障碍节点已不存在，进入 `LOG(FATAL)` 分支并终止进程。这与用户观察到的语言切换在时间上有关，但现有证据不能证明具体哪处界面或哪一次语言切换导致节点失效，不能宣布该闪退已经完全修复。

## 调查依据

- 安装版使用 Electron 25.9.8 和 Chromium 114.0.5735.289。转储中的主程序标识与 Electron 25.9.8 官方 Windows 符号文件匹配，符号标识为 `0C33781670B803FD4C4C44205044422E1`。
- 使用调试器读取主线程调用栈，并用上述官方符号对应到 `logging::LogMessage::~LogMessage` 和 `content::BrowserAccessibilityComWin::get_hyperlink`；其调用链包含 `UIAutomationCore.dll`。
- 转储中的引擎诊断信息表明：超链接序号为 0，缓存的超链接数量为 2，其中一个标识无法取得对应节点。父节点角色是普通容器，标签为 `div`，没有足以识别业务组件的类名或属性；不能仅据此推断它属于特定页面。
- [Chromium 114 对应源码](https://raw.githubusercontent.com/chromium/chromium/114.0.5735.289/content/browser/accessibility/browser_accessibility_com_win.cc)中，这一失效节点分支会在部分情况下记录致命日志，否则返回失败状态。有关同一函数的[上游问题记录](https://github.com/electron/electron/issues/39574)也将问题归于 Chromium 路径。
- 对 Chromium 114、118、120、122、124、126、128、130、132、134、136、138、140、142、144 及主线的相关源码抽样检查，失效节点分支均仍包含致命日志。各版本的触发条件可能不同，抽样本身不能代表所有版本或所有场景。

## 隔离复现与验证范围

使用已安装的 Windows 程序，分别创建临时空白配置，模拟通过实际语言菜单切换中文和英文，确认页面语言标识发生变化；四轮共完成 320 次切换，进程均未闪退。这个结果只说明这 320 次操作没有复现问题，并不能证明不会发生闪退。

同时尝试用 Windows UI 自动化遍历同一隔离程序，包括启用渲染器无障碍支持；采集到的是图形窗格，没有访问到文档文本模式，文本查询次数为 0。因此这些尝试未覆盖转储中的超链接查询路径，不构成无障碍压力测试通过。未关闭或禁用应用的无障碍能力。

## 后续处理建议

1. 保留用户原始转储并避免上传；如再次发生，基于对应版本的符号核对调用栈和节点结构，继续调查触发位置。
2. 减少语言切换期间大批量改写已有界面节点可以降低界面树变化频率，但不能单独证明原生问题已消失，应以回归结果为准。
3. [Chromium 官方说明](https://developer.chrome.com/blog/windows-uia-support-update)称，Chromium 138 起默认使用原生 UI 自动化提供程序，保留原有 MSAA 和 IA2 支持；[Electron 37](https://www.electronjs.org/blog/electron-37-0)首次搭载 Chromium 138，但该版本现已停止维护。可以在隔离环境评估仍受支持的 Electron 版本，并实测项目兼容性、屏幕阅读器、UI 自动化和语言切换；升级不会自动证明 IA2 路径的致命分支已经消除。
4. 当前 Chromium 114 有 `--enable-experimental-ui-automation` 实验开关，不应在未经充分兼容性及无障碍验证时直接引入正式包，更不能通过禁用无障碍来掩盖问题。
5. 若必须从根本上移除当前失效节点分支中的致命退出，可以评估维护自定义 Electron 构建，使该分支返回错误并保留无障碍功能。此方案需按照[官方 Windows 构建说明](https://www.electronjs.org/docs/latest/development/build-instructions-windows)补齐工具链、下载完整源码并维护引擎补丁；本机已发现缺少部分构建工具和组件，编译时间尚未实测。必须分别验证引擎二进制、所有受支持平台及正式发行包，不能将未完成的定制构建算作修复。
