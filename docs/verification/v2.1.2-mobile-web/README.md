# 2.1.2 移动端与 Web 同步验收

应用版本 2.1.2，移动构建号 20102。本次独立构建 Android、HarmonyOS、Web，将桌面已验证的富文本、字符集、默认对齐、自定义页边距、列宽自适应和图片插入修复纳入三个平台。移动宿主、应用身份及签名配置沿用。

## 格式和交互

Android、HarmonyOS 和 Web 的当前生产构建各通过 7 组、43 项浏览器检查，覆盖核心功能、阅读手势、编辑、工作区、脑图/流程图、助手及本轮新增格式编辑专项。新增专项真实打开 XLSX，调整列宽后写盘重开，核对富文本分段、中文字符集、自定义六项页边距、空表与列宽；在手机编辑视图粘贴/拖入 PNG，验证实际解码、撤销重做和 SLDOC 保存读回。

浏览器宿主从待测构建读取平台，不再写死 Android。HarmonyOS 报告明确使用 `platform: harmony`。Android 又从实际解压后的发行源码目录完整重放 43 项检查，与归档资源指纹一致。原生 UTS 检查分别使用 app-android / app-harmony 编译，验证其输出静态资源与冻结快照一致。

传统 XLS 在有可用转换服务时，通过已有授权弹窗使用完整引擎，保留格式；取消或失败不能静默降级。离线路径保留原功能，并继续明确说明其高级格式限制。兼容警告跟随实际转换结果对象，不用全局开关推断，避免并发文件或登录状态变化造成误报。未支持的对象和宏继续提示。

用户 BIFF 样本仅在本机测试：移动适配器读取 → 编辑 → 保存 XLS → 再读取，核对未修改单元格、工作表、页边距和原文件字节；另执行共享实际编辑模型的 XLS 往返专项。源文件没有上传到仓库、线上服务或发行附件。

## 大小与资源

| 平台 | ZIP 字节数 | 实际解压字节数 | 文件数 |
| --- | ---: | ---: | ---: |
| Android | 38,531,176 | 59,799,985 | 59 |
| HarmonyOS | 38,531,184 | 59,799,985 | 59 |

Android 两项严格按 60,000,000 字节上限检查。两包分别构建、检查和冻结，平台元数据与原生编译输出一致，所有 ZIP CRC 及逐文件 SHA-256 均通过；字库完整，不裁字。共用编辑器字节可能相同，平台编译、宿主源码与元数据分别验收。

发行包与实际解包项目均在 `release/v2.1.2/mobile-web/`。`android-source.json`、`harmony-source.json` 记录完整清单及实际解压检查；`web-source.json` 记录独立 Web ZIP 的 38 项资源校验。原 `verified/` 移动快照和原桌面附件不覆盖；补充发行使用 `v2.1.2-mobile-web` 标签。

## 测试与部署证据

- `verification.json`、`unit-regression.json`：全量前端、主进程、服务端、移动与打包测试，以及条件样本的单独执行记录。
- `android-browser.json`、`harmony-browser.json`、`web-browser.json`：三个生产构建的 43 项检查与构建指纹。
- `native-compilation.json`：两个平台各自的 UTS 编译与资源匹配检查。
- `public-web.json`、`public-format-editing.json`：公开地址的同域资源、权限、现有功能和本轮修复实际编辑验收。
- `promo.json`：新 PC 横版与 Android 竖版视频的来源、画幅、解码、音轨、字幕及画面核验；Android 显式取本次 sync 冻结快照。
- `source-inputs.json`：本次构建、测试及发布使用的源码指纹。

Web 部署先创建独立静态目录并检查候选配置，保留旧会话需要的哈希资源，再原子切换前端；核对现有后台和管理入口、同域 API 及匿名拒绝策略。公开验收失败会回滚前端指针及配置。云账号数据和后台代码不随本次前端部署迁移。

此前审核脚本 `harmony-review.cjs` 使用已移除的“全部功能”导航入口，不能用于当前布局；原历史文件保留。本次采用当前 7 组生产测试、Android/Harmony 实际平台宿主标识、原生编译及公共桥接契约测试验收，不将该历史脚本的选择器失败计为应用通过结果。

上述浏览器使用隔离配置和模拟原生传输；不等同于新签名 APK / App Pack 的设备验收。两份交付是可提交云打包的源码项目。安装包返回后，使用对应冻结源码进行身份、平台、版本和资源核验，再验证签名和实际设备行为。
