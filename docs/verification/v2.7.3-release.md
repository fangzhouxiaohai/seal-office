## 三、PDF 清晰度实测

方法：用正式导出链路 `main/pdfExport.js` 的 `createPdfFromHtml` 在 Electron 25.9.8 中生成 PDF，再解析文件结构。

| 项 | 实测值 |
| --- | --- |
| 页面 | 1 页，MediaBox 594.96 × 841.92pt（A4） |
| 位图 | 0 个 `/Subtype /Image` |
| 字体 | 内嵌 `MicrosoftYaHei`、`MicrosoftYaHei-Bold` 子集（CIDFontType2 / Type0，2 个 FontFile2） |
| 正文版心 | 174 × 257mm（A4 减 18mm 左右、20mm 上下边距） |
| 文字 | 矢量文字（内容流为 Tj/TJ 文本操作，字号 22 / 14） |

结论：导出 PDF 为矢量文字并内嵌字体，不存在整页位图；此前“模糊”来自导出 HTML 缺少基础样式（浏览器默认 16px 衬线体、无行距与段距）以及字体未就绪就打印。

## 六、2.7.3 修订（按用户装机实测反馈）

用户在 2.7.3 首轮安装包上复测出两个云同步问题，本轮修复后重新打包：

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 云端文件已删除后，本地修改一直提示“上传失败：云文件不存在或已删除”，待同步列表重试无效 | 本地保存的云节点映射（`state.links`）仍指向已删除节点，上传预检返回 404，队列长期滞留 | 主进程新增 `forget` 操作清除失效映射与队列；渲染层识别该 404 状态后调用 `forget` 并重新保存一次，按新文件重新加密上传 |
| 提示“云端已保存”，但标签仍是未保存状态 | 自动保存只写本机文件与云端，没有清除保存标记 | 本机写入成功且快照未再变化时调用 `markDocumentSaved` / `保存PDF文档`，清除未保存标记；写入期间又有修改则保留 |

## 七、macOS DMG 说明

- 产物：`seal-office-2.7.3-macos.dmg`，arm64，229,562,834 字节，SHA-256 `88126f51…fd456`，应用标识 `com.sealoffice.desktop`。
- 生成方式：`node scripts/macos_cross_build.cjs` 交叉构建（官方 Electron 25.9.8 darwin-arm64、@electron/packager 20.3.0、rcodesign 0.29.0 临时签名、Zapp 1.6.0 制盘），构建记录为 `work-arm64/验收记录.json`，其中 `releaseReady: false`。
- 签名状态：**临时签名（ad-hoc），未经 Apple 开发者证书签名、未公证**。首次打开需要在“系统设置 → 隐私与安全性”里选择“仍要打开”，或右键打开；Gatekeeper 会提示来源未知。这是无证书打包的预期行为。
- 校验范围：构建工具核对了应用结构、Info.plist 身份、文件关联、ASAR 完整性、14 个符号链接、16 个 Mach-O 架构、DMG 文件集合与摘要，并通过 `hdiutil` 等价的镜像校验；**未在真实 Mac 上做签名、Gatekeeper、安装、启动与卸载验收**。
- 未生成 x64（Intel）DMG：本机交叉构建需要单独的 darwin-x64 依赖与 Electron ZIP，本轮只交付 Apple Silicon 包。Windows 上的 x64 与 arm64 双架构包需要 macOS 上的 `lipo`/`@electron/universal`，本机无法合并。
