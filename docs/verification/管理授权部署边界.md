# 管理授权数据与部署边界

新增管理员、角色、菜单配置和授权操作审计存于服务数据目录中的独立 `admin-rbac.sqlite`。原环境变量管理员仍是超管，不创建默认账号或默认密码；原业务数据库与已有业务记录无需迁移。管理员和角色变更、新的业务操作只写入本次新增记录。

授权库采用进程内数据库快照并以数据目录真实路径派生的本机回环端口进行排他。相同数据目录只允许一个云服务进程，端口被占用时安全拒绝启动；进程意外结束后由操作系统释放监听。此机制只适用于**同一主机、同一网络命名空间**，不支持多个容器、多个宿主机或不同网络命名空间共享该数据目录。不能依靠共享卷或多个独立网络命名空间横向扩容；迁移到此类部署前必须更换支持跨节点事务和锁的授权存储。

云服务独立部署器仅支持现有单机 `seal-cloud.service`：预检确认服务处于活动状态、主进程工作目录对应 `current`，且服务与部署进程使用同一网络命名空间。部署器冻结服务源码和依赖摘要，在独立数据目录启动候选，切换前核对后台、PHP、Nginx、Web 和历史 `previous-release` 的基线；切换失败恢复原服务指针。切换前还应确认数据目录派生的锁端口未被无关程序占用；端口冲突会阻止启动，不能通过绕过锁处理。

旧后台可通过原环境超管与更新后的 Node 服务继续工作；新 PHP 后台的会话资料依赖 Node 新增的 `/v1/admin/session`，因此上线顺序须先完成 Node 服务的兼容切换与验收，再切换 PHP 和前端，不能把新 PHP 先接到旧 Node。前后两步均需独立备份和验证，遇到断线必须只读核对实际指针和服务状态，不能盲目重复切换。

普通管理员的权限在服务端逐请求重新计算；菜单隐藏仅影响导航，菜单停用会阻断对应业务接口，系统授权管理菜单不得停用或隐藏。审核附件传输期间撤权会中止尚未发送的数据，已经发送或被网络缓冲的数据无法收回。上传和 JSON 写请求在写入提交前再次鉴权；转换设置撤权时回滚工作进程配置。
