# 项目后台文档转换

转换服务与现有海豹办公管理后台部署在同一台项目服务器。管理员登录 https://seal.xingmasoft.com 后进入“文档转换”。手机/H5 使用 `https://seal.xingmasoft.com/api/office-converter`；无需另建第三方转换账号。

账号列表手机号采用“前 3 位 + **** + 后 4 位”显示。管理员概览接口直接返回脱敏号码，页面也在载入时保护显示，完整手机号不进入账号表格或搜索状态；搜索支持号码可见片段和账号标识。此修改只影响管理员展示，验证码和用户登录继续使用原有号码记录。

## 后台操作

页面显示引擎版本、启停状态、并发上限、本次启动成功/失败次数和最近 100 个任务。任务仅含格式、大小、时间、结果与失败原因，不记录文件名或正文，重启后重新统计。

访问令牌仅在生成或重置后的弹窗中显示一次，平时只显示哈希指纹。复制到手机“设置 → 文档格式兼容”，填写服务地址与令牌，保存后测试连接。重置会让手机原令牌失效，需要重新填写；取消不会修改配置。启用前必须准备引擎与令牌。暂停拒绝新任务，已经开始的任务继续完成。

“测试真实文档转换”创建一份合成的 Word 2003 XML，输出真正的 DOC 二进制，再转换回 DOCX，检查中文与 `0012` 前导零。服务有正在运行的任务时拒绝管理测试，避免抢占手机任务。配置修改、令牌重置和管理测试记入既有后台操作记录。

## 架构与部署文件

| 组件 | 位置/入口 |
| --- | --- |
| 既有云 API 和管理页面 | `/www/wwwroot/seal.xingmasoft.com/current`，127.0.0.1:8096 |
| 转换管理配置 | 持久化 `data/converter-settings.json`，权限 0600，只保存客户端令牌 SHA-256 |
| 私有转换运行环境 | `/opt/seal-office-converter/runtime`，Debian bookworm 用户态与独立 Node/LibreOffice/中文字体 |
| 工作进程源码 | rootfs 中 `/app/server/converter` 与 `/app/main/documentFormats.json`，保持仓库目录结构 |
| 工作进程 | `seal-office-converter.service`，非 root 用户 seal-converter，回环端口 8298 |
| 管理控制通道 | `/internal/*`，独立管理令牌，仅云 API 经回环地址访问 |
| 手机公开接口 | `GET /api/office-converter/v1/capabilities`、`POST /api/office-converter/v1/convert` |

源码中的 `server/deploy/prepare-converter-runtime.sh` 安装专用运行环境，要求事先下载并核验官方 Debian amd64 rootfs 层与 Node Linux x64 包；不升级宿主机系统库。初次安装后复制工作进程源码、创建 seal-converter 系统用户，并安装 `seal-office-converter*.service`。Debian 软件包由 apt 的发行签名和文件哈希校验，中文字体与引擎许可证保留在运行环境内。

生产部署使用 Debian 官方镜像 `bookworm-slim` 的 amd64 manifest `sha256:a4672c0cb26fbdde88e38fa2dfb6c681942306680e41e4378b28770b6e79ee91`。基础层 SHA-256 为 `7fd1ebe418b5079d4aa36f416af9b143d127bc75b0155d71cb5fd559b5e04d39`，Node v22.23.3 Linux x64 包 SHA-256 为 `df450af89261115ef9f9e3830c3eeb2cc9213b63c720b1af623cb5dcbe2e02de`。镜像来自 [Debian 官方 Docker 镜像](https://hub.docker.com/_/debian)，Node 包与校验文件来自 [官方发行目录](https://nodejs.org/dist/v22.23.3/)。服务器运行版本以验收报告为准；宿主机原有系统版本未更换。

root 所有的 `/etc/seal-cloud/converter.env` 设置 `PORT=8298` 和随机 `SEAL_CONVERTER_CONTROL_TOKEN`。现有 `/etc/seal-cloud/service.env` 添加相同管理令牌、`SEAL_CONVERTER_INTERNAL_URL=http://127.0.0.1:8298`、`SEAL_PUBLIC_ORIGIN=https://seal.xingmasoft.com`，保留已有短信与管理员设置。管理令牌和客户端令牌均不得提交仓库。

专用 proc 文件系统由 `seal-office-converter-proc.service` 管理。工作进程使用 RootDirectory、独立临时目录、NoNewPrivileges、空 CapabilityBoundingSet、2 GiB 内存上限和进程数限制。该部署隔离运行库与文件系统，仍共享宿主机内核。引擎和字体从 Debian 软件包更新，不应在宿主机直接安装另一套 LibreOffice。

现有站点使用 `server/deploy/nginx-https.conf` 的专用路由：只将 `/api/office-converter/v1/` 转给 8298，其余转换路径返回 404，管理通道不公开。单文件 20 MiB，Base64 请求入口限制 29 MiB，转换最长 90 秒，客户端每 IP 每分钟最多 20 次请求，并发在后台选择 1 或 2。管理测试允许两次串行转换的响应时间。

## 更新和回滚

先构建管理页面并测试：`node server/admin/build.cjs`、`npm --prefix server test`、`node --test server/converter/test.cjs`。后台服务部署仍采用现有 releases/current 目录结构；云服务源码位于 release 根目录，转换进程使用前述完整仓库布局。

切换前保存现有服务环境文件、本站 Nginx 配置和 current 指向，并运行既有一致性备份脚本。新 release 准备完成后，原子切换 current，重启项目 API，检查就绪，再校验并重载 Nginx。失败时恢复旧 current、环境和 Nginx，保留 data，不用备份覆盖正在使用的用户资料。只重启本项目相关服务。

工作进程重启会清空任务统计，云 API 在状态读取时或最多 15 秒内恢复启停、并发与令牌哈希配置。部署后检查 admin 登录、转换鉴权、管理通道隔离、真实 DOC 往返及手机生产页面读取/保存往返。实际报告见 `docs/verification/backend-converter/`。APK 和 iOS/鸿蒙真机验收仍与服务端验收分别记录。
