## 二、包（安装器）要求

官方文档 [Upload app packages for MSI/EXE app](https://learn.microsoft.com/en-us/windows/apps/publish/publish-your-app/msi/upload-app-packages) 的硬性要求：

1. **Package URL**：必须是可安全访问的版本化 URL，直接指向安装器本体；商店从该地址下载并缓存。**提交后该地址的二进制不能再变**，否则会触发重新认证。
2. **必须是无提示可安装的安装器**：商店以静默方式安装。EXE 类型需要在「安装程序参数」里给出开关（示例写作 `/s`，实际由安装包决定）；如果安装器默认静默则勾选对应选项。
3. **必须是独立/离线安装器**，不能是运行时再去下载二进制的下载器。
4. 体系结构 x64，语言需在商店支持列表内（中文各变体均支持）。

本安装包的实测结论（`electron-builder` 的 NSIS 安装器）：

| 调用 | 结果 |
| --- | --- |
| `SealOffice Setup 1.8.3.exe /S /D=<目录>` | 退出码 0，**8 秒完成，全程无窗口**，程序文件落盘，"添加或删除程序"写入 `DisplayName=SealOffice 1.8.3`、`Publisher=seal-office` |
| 同参数小写 `/s` | **NSIS 开关区分大小写**，小写会弹出安装向导（`oneClick: false` 的向导流程） |

因此商店表单里的参数必须是**大写 `/S`**；双击安装的用户体验不受影响，仍显示完整向导。

> 注：Partner Center 页面在填写参数时若用脚本直接改 DOM 值会被后端存成小写 `/s`，必须用真实键盘输入，才能保存为大写 `/S`。

## 三、托管 URL 的坑（务必先自检）

2026-10 复检时曾出现：`https://tsweb.teach-assistant.com/SealOfficeSetup1.8.3.exe` 返回的不是安装包，而是另一个项目（天山恋管理后台）的 635 字节 `index.html`。实测该站点的静态文件只在 `/assets/` 下可达，其余路径一律被单页应用兜底规则接管：

```
/assets/index.052fd3fb.js        → 200 application/javascript
/favicon.ico                     → 200 text/html 635
/SealOfficeSetup1.8.3.exe?x=1    → 200 text/html 635
/downloads/SealOfficeSetup1.8.3.exe → 200 text/html 635
```

同站重新放回文件后已恢复正常（`200 application/octet-stream`，`Content-Length` 与本地文件一致）。**每次更新部署后都要重新自检该 URL**，否则商店下线的是 HTML 页面。可选方案：

1. **同站静态目录**：把安装器放进该站点确实会静态提供的目录（例如 `/assets/`），或调整 Web 服务器，让 `\.exe$` 请求走静态文件、不被 `try_files` 兜底到 `index.html`。
2. **GitHub Releases（推荐）**：把安装器作为 Release 资产上传，得到形如
   `https://github.com/fangzhouxiaohai/seal-office/releases/download/v1.8.3/SealOfficeSetup1.8.3.exe`
   的稳定直链，走 GitHub CDN，与开源项目定位一致。
3. **对象存储**：阿里云 OSS / 腾讯云 COS / Cloudflare R2 等，注意设置公开可读与正确的 `Content-Type`（`application/octet-stream` 或 `application/vnd.microsoft.portable-executable`）。

更换 URL 后：在 Partner Center 的「包」一节更新 Package URL（或走「更新提交」），点「全部保存」，再点「再次运行」重跑包验证。

| 项目 | 值 |

| 该版本实测 | `/S` 静默安装退出码 0、**9 秒、全程零窗口**；主程序落盘；添加/删除程序条目 `DisplayName=SealOffice 1.8.3`、`Publisher=seal-office`、`DisplayVersion=1.8.3`；静默卸载退出码 0、无残留 |

说明两点，避免误判：

- **重新构建的字节不会完全相同**：NSIS 会把构建时间戳写进产物，因此同一份代码两次构建的大小可能一致而 SHA-256 不同。核对“线上是否为新版本”应看**构建来源与功能**，而不是只比哈希。
- 当前本地构建与线上这份的差别只有 `package.json` 里一行 `win.signtoolOptions.publisherName`（未签名时对安装包行为无影响；实测该字段不改变添加/删除程序里的 `Publisher`，该值来自 `author`）。因此线上这份**包含 1.8.3 的全部功能**，无需为此重传。

## 三点五、认证结果：EXE/MSI 路线被策略 10.2.9 拒绝，改走 MSIX

2026-10-07 提交认证后**评审失败**，报告写明：

> **10.2.9 安全 - 包提交**：该二进制文件及其所有可移植可执行文件（PE）必须用代码签名证书进行数字签名，该证书与由 Microsoft 可信根程序（Trusted Root Program）旗下的证书授权机构（CA）颁发的证书链接。
> 如果您的 EXE 或 MSI 无法符合 Microsoft Store 10.2.9 的策略，您可以考虑将现有的 EXE 或 MSI 重新打包为 **MSIX** 格式。Microsoft Store 为 MSIX 格式提供了许多免费福利，如**代码签名、托管服务**等。
> 受影响的软件包：`https://tsweb.teach-assistant.com/SealOfficeSetup1.8.3.exe`，编码唱法类型：**无符号**，描述：包应使用 SHA256 或更高级别算法签名。

结论：**未签名的 EXE/MSI 无法上架**。两条出路——

1. 自购代码签名证书（Azure Trusted Signing 约每月 10 美元，或 OV/EV 证书），继续用现有 EXE/MSI 产品；
2. **重新打包为 MSIX**（官方推荐，商店代签、代托管，零成本）——本项目采用这条。

报告同时提醒一个名称约束：**若要用同一个名称管理 MSIX 打包应用，必须先在 Partner Center 中删除现有 Win32 应用中的应用名称**（保留名称在两个产品间不能重复）。

### 用 scripts/build-msix.ps1 打 MSIX

```powershell
# 自测（占位身份）
pwsh -NoProfile -File scripts/build-msix.ps1

# 提交商店（身份三项必须与 Partner Center 的 MSIX 产品完全一致）
pwsh -NoProfile -File scripts/build-msix.ps1 `
  -IdentityName '<包/标识/名称>' `
  -Publisher 'CN=<Partner Center 分配的发布者>' `
  -PublisherDisplayName '星马软件' `
  -Output 'release\v1.8.3\SealOffice 1.8.3 商店版.msix'
```

要点与实测：

- **不走 electron-builder 的 appx 目标**：它会在构建途中从 GitHub 拉取示例磁贴资源，本机到该主机不通（构建以 `read ECONNRESET` 失败）。`scripts/build-msix.ps1` 直接用 `makeappx` 打包，全程离线。
- **makeappx/signtool 免安装取得**：`Microsoft.Windows.SDK.BuildTools` 的 NuGet 包解压即得（不需要安装 Windows SDK、不需要管理员），本机用的是 `10.0.28000.2705`。
- **磁贴资源**在 `build/appx/`：`Square44x44Logo.png`、`Square150x150Logo.png`、`Square310x310Logo.png`、`Wide310x150Logo.png`、`StoreLogo.png`、`SplashScreen.png`，底色取应用品牌色 `#2b6cf6`（`renderer/src/styles.css` 里的 `--brand`）。
- **清单要点**：`EntryPoint="Windows.FullTrustApplication"` + `<rescap:Capability Name="runFullTrust" />`（桌面应用必需），`Version` 必须四段（写 `1.8.3.0`）。
- **本机试用**：加 `-Sign` 会用自签名证书签名；把该证书导入“受信任人”后即可 `Add-AppxPackage` 安装试用（仅供本机，提交商店不需要——商店会用自己的证书重签）。
- **产物**：`release\v1.8.3\SealOffice 1.8.3.msix`，实测 167,039,423 字节（159 MB）、`makeappx unpack` 可正常解出清单与 `SealOffice.exe`。
- **商店版的行为差异（重要）**：MSIX 运行在容器中，注册表写入会被虚拟化，因此**资源管理器“新建”菜单与“自动设为默认程序”在商店版里不会作用于真实系统**（功能仍在，但不会改动用户的真实关联）；文件打开、拖入、编辑等主要功能不受影响。

## 六、自动化填表经验（避免重复踩坑）

Partner Center 的页面是 Angular 应用，脚本操作有几处必须注意：

- **文本与选择必须用真实输入**：用 `element.value = x` + `dispatchEvent` 改值，界面看起来变了但**数据模型收不到**，保存后为空；要用 CDP 的 `Input.insertText`（配合 `setSelectionRange` 全选）才能落库。
- **`he-button` 与自定义元素**：`innerText` 常为空，按文本找不到按钮，应直接用 id（例如保存是 `#save-draft`）或坐标点击。
- **列表行的元素 id 会变**：点「添加更多」新增行后，行内输入框的 `formly_<n>` 前缀会变化，不能按固定前缀找行，要按所在容器（`#repeat-horizontal-<list>-addMore` 的父容器）枚举。
- **上传成功不等于提示消失**：文件上传后拖放区仍显示「单击以浏览」，判断是否挂上应读图片的 `naturalWidth/naturalHeight`（商店素材会出现在 CDN 域名下）。
- **各列表的锚点 id**：产品功能 `#repeat-horizontal-productFeatures-addMore`、其他系统要求 `#repeat-horizontal-requirements-addMore`、关键字 `#repeat-horizontal-searchTerms-addMore`。
