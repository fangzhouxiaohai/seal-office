# 字体读取、自定义导入与专属格式嵌入

本文记录 2.2.0 的跨平台字体方案。目标不是把所有字体“安装到系统”，而是让海豹办公直接读取系统字体、导入不进入系统字体库的字体，并在自己的文件格式中携带实际使用的字体字节。

## 1. 平台能力

| 系统 | 系统字体读取 | 自定义字体导入 | 专属格式嵌入 |
| --- | --- | --- | --- |
| Windows | 扫描 `%WINDIR%\Fonts`、`%LOCALAPPDATA%\Microsoft\Windows\Fonts` 及安装包附带字体；支持 TTF / OTF / TTC | 文件选择器导入，复制到用户数据目录，不写系统字体库 | 支持；TTC 按字面拆出独立字面 |
| macOS | 扫描 `/System/Library/Fonts`、`/System/Library/Fonts/Supplemental`、`/Library/Fonts`、`~/Library/Fonts` | 同上 | 支持 |
| Linux | 扫描 `/usr/share/fonts`、`/usr/local/share/fonts`、`~/.fonts`、`~/.local/share/fonts`，并合并安装包附带字体 | 同上 | 支持 |
| Android | WebView 不提供可枚举的字体文件接口；提供系统通用字体组、安装包内思源字体，并可导入字体 | 通过系统文件选择器导入到应用沙盒 | 支持导入字体的嵌入；系统字体文件不向应用公开 |
| HarmonyOS | 原生层调用 `@ohos.font.getSystemFontList()` / `getFontByName()` 取得系统字体名称与字重 | 通过系统文件选择器导入到应用沙盒 | 支持导入字体的嵌入；系统字体文件路径不向 WebView 公开 |
| Web / PWA | 浏览器不公开系统字体枚举；提供通用字体组和安装包内思源字体 | 通过文件选择器导入到 IndexedDB 文档空间 | 支持导入字体的嵌入 |

Android / HarmonyOS / Web 的“系统通用字体”不是伪造安装字体，而是 `sans-serif`、`serif`、`monospace` 三个跨平台通用族；另有 HarmonyOS 原生返回的真实系统字体名称。系统字体名称只在当前设备上解析，第三方文档仍可能因设备没有同名字形而回退。

## 2. 实现入口

- `main/fonts/fontMeta.js`：只读解析 OpenType/TrueType 的 `name`、`OS/2`、`head`、`cmap`；读取中文名、英文名、PostScript 名、字重、斜体、`fsType` 嵌入授权、中文/拉丁字形覆盖；从 TTC 拆出单个字面并重新计算 `head.checkSumAdjustment`。
- `main/fonts/fontService.js`：跨平台目录扫描、字体缓存、自定义字体库、重复检测、删除、读取字面。字体缓存按路径、修改时间和大小失效。
- `main/ipc/fontChannel.js`、`main/preload.js`：桌面 IPC `font.list` / `font.read` / `font.import` / `font.remove` / `font.folder`。
- `mobile/web/bridge.ts`：移动与 Web 共用同一组字体通道，导入文件写入 `/seal/private/fonts`，清单写入 `/seal/private/fonts.json`。
- `renderer/src/fonts/fontManager.ts`：字体目录、`FontFace` 注册、字体回退链、文档字体收集、专属格式字体资源生成和读取时注册。
- `renderer/src/fonts/FontPicker.tsx`：可搜索字体选择器，按文档嵌入、我的字体、系统字体、内置字体、系统通用字体分组，带真实字形预览和导入/管理入口。
- `renderer/src/fonts/FontLibraryCard.tsx`：设置中心的字体管理，显示系统字体数量、导入、移除、重新扫描和字体目录。

## 3. 自定义字体不是系统安装

导入字体只复制到应用自己的数据目录：

- Windows / macOS / Linux：`<userData>/fonts/`
- Android / HarmonyOS / Web：应用文档空间 `/seal/private/fonts/`

因此不需要管理员权限，也不会改动系统字体库或其他软件。删除只删除海豹办公的副本；系统字体和已保存文档中嵌入的字体不受影响。

导入时校验扩展名（TTF / OTF / TTC）、文件大小（单文件 96 MiB）、字体表和名称；同一 SHA-256 字体不会重复复制。TTC 会拆成多个字面记录，可分别出现在字体下拉框中。

## 4. 专属格式的字体嵌入协议

不改变容器版本：`.sldoc` / `.slxls` / `.slppt` 仍是 `seal-office` 版本 1、三个 ZIP 条目（`mimetype`、`manifest.json`、`document.json`）。字体资源放在 `document.json` 的编辑模型内，因此旧版海豹办公仍能读到正文，未知的 `字体资源` 字段由旧版忽略；新版在渲染前先注册字体。

保存时写入：

```json
{
  "字体格式": 1,
  "字体资源": [{
    "标识": "system-…",
    "名称": "仿宋_GB2312",
    "家族": "仿宋_GB2312",
    "别名": ["FangSong_GB2312"],
    "样式": "Regular",
    "字重": 400,
    "斜体": false,
    "格式": "ttf",
    "文件大小": 10578152,
    "数据": "<完整字体文件 base64>",
    "数据指纹": "<sha256>"
  }],
  "字体嵌入限制": [{ "名称": "…", "原因": "字体授权不允许写入文档" }],
  "字体缺失": ["…"]
}
```

规则：

1. 只嵌入文档实际引用的字体：文字扫描 `font-family` / `<font face>`，表格扫描单元格与富文本格式，演示扫描主题字体、文本框和片段字体。
2. 完整字体文件最多合计 56 MiB；超过时记录 `字体嵌入限制`，不静默截断字形。
3. 只对 `fsType` 允许可编辑嵌入的字体写入字节。系统字体可能受厂商授权限制（例如本机 PingFang 字体的 `fsType` 不允许可编辑嵌入），此时不回退为“假装能保证”。
4. 读取时先注册 `字体资源` 中的字体，再渲染 HTML / 表格 / 演示；同一文档在另一台设备上不依赖本机是否安装该字体。
5. 打开后再次保存时，已加载的嵌入字体字节会继续保留，即使本机没有对应字体文件。
6. 旧文档没有 `字体资源` 时仍按原协议打开；缺失字体通过回退链和提示说明，不修改内容。

### 边界

- 专属格式可以保证“文档携带了实际使用字体的完整字节”时跨设备字形一致；无法保证源字体文件不可读取、授权禁止嵌入或总量超限时仍然 100% 还原。此时文档会留下可审计的限制记录，并明确提示，不伪称已嵌入。
- 旧版客户端忽略字体资源时只能用本机字体；要获得跨设备保证，需要 2.2.0 或更高版本打开。
- 不把系统字体文件复制进安装包，也不绕过字体授权。安装包只附带 SIL OFL 授权的 Noto Sans SC / Noto Serif CJK SC。

## 5. DOCX / WPS 兼容策略

第三方 DOCX / XLSX / PPTX 不包含可编辑字体字节，字体名称只是引用。海豹办公采用“保留原字体名 + 追加本地回退链”的方式：

- 读取时保留 `仿宋_GB2312` 等原始字体名，在 CSS 中追加 `Noto Sans SC`、`SealNotoSans`、`PingFang SC`、`Microsoft YaHei` 等本地回退。
- 常见公文字体建立独立映射：`仿宋_GB2312`、`楷体_GB2312`、`方正小标宋简体`、`方正仿宋简体`、`方正黑体简体`、`方正楷体简体`、`华文中宋` 等优先映射到同机兼容字体和思源字体。
- 表格与演示渲染也使用同一回退链；保存回 DOCX / XLSX / PPTX 时仍写入原字体名，不把替代字体名写回来源。
- 只对 `_GB2312`、`方正`、`华文`、小标宋、书宋等会明显改变公文版式的专用字体提示缺失；系统有通用无衬线/衬线回退的普通字体不反复打断打开。

因此第三方文档只能“尽量兼容”，不可能在字体未随文件提供、设备也未安装时保证 100% 一致；海豹专属格式才通过字体嵌入承担更强的跨设备保证。

## 6. WPS 字体路径静态观察

2026-10-26 对已安装的 WPS Office `12.1.0.26895` 做只读静态检查，未执行或复制第三方代码、字体或资源：

- 目标：`kwpsfauxfont.dll`，大小 1,746,424 字节，SHA-256 `2a3983eb39568fbb8ff45dab4cb3e4289dc1ce61dab8075858fe1958d8f67302`。
- 可观察字符串：`fauxFontMake:: faux_name:%1 faux_hash:%2 fallback_index:%3`、`regFauxFontQueryWrapper`、`regFauxFontStyleQueryWrapper`、`addApplicationFontFromData(QFontDatabase…)`。
- 观察结论：WPS 存在按缺字/字体哈希/回退序号生成替代字体的路径，并能从内存数据向应用注册字体；这与其字体不必安装到系统即可使用的行为方向一致。
- 限制：这是静态字符串与模块清单，不证明运行时的具体替换表、优先级、云字体下载或所有文档类型。海豹办公的实现独立采用浏览器 `FontFace` + 自有回退表和专属格式字体资源，不包含 WPS 代码或商标资源。
