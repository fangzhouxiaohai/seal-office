# 海豹办公打包规范

版本读取根目录 `package.json`，桌面、服务端、移动端版本与云打包构建号同步；应用身份、签名与现有中文显示名保持。文件名统一读取 `build/artifact-names.json`，微软商店清单两处显示名使用已保留的 `seal-office`。

## 目录

每次打包先运行 `npm run release:prepare`。本机 `release/` 顶层只允许当前 `v<版本>/` 和 `promo/`，只保留一个版本目录；旧版本本机二进制可以清理，远端历史发行与历史验收报告不修改。所有安装包、Web ZIP、移动云打包源码 ZIP、校验文件、`win-unpacked`、`linux-unpacked` 与 MSIX 布局均归入当前版本目录，禁止在 `release/` 顶层单独放安装包。

```text
release/
  v2.1.1/
    seal-office-setup-2.1.1.exe
    seal-office-2.1.1-portable.exe
    seal-office-2.1.1-microsoft-store-x64.msix
    seal-office-2.1.1-amd64.deb
    seal-office-2.1.1-web.zip
    win-unpacked/
    linux-unpacked/
    SHA256SUMS.txt
  promo/
    seal-office-2.1.1-pc-intro-1080p.mp4
    seal-office-2.1.1-android-intro-1080p.mp4
```

Android/Harmony 云服务返回文件须先校验版本、身份、内置资源和签名，再按英文规则归档。不把云打包源码 ZIP 称为 APK/HAP。微软商店上传用未签名 MSIX 与可直接旁加载的已签名 MSIX 分别标明。

四种默认专属后缀为 `.sldoc`、`.slxls`、`.slppt`、`.spdf`，Windows、Linux、Web、Android 和 HarmonyOS 使用同一容器协议。发行验收须覆盖打开、编辑、连续保存、另存为、关闭重开及云端文件入口；旧 `.sealdoc`、`.sealsheet`、`.sealshow` 继续兼容。Windows 右键新建模板必须是有效容器，不能用空文件占位。新增移动桥接修改还须验证真实 SDK 发出的普通 JSON 对象消息与启动握手，浏览器模拟宿主不能冒称原生设备验收。

## 检查与构建

先完成类型检查、渲染层与主进程完整回归、云服务回归、移动桥接检查和生产浏览器分组回归；涉及账号删除还要验证隔离备份、故障重试、其他账号保留和恢复过滤。测试真实字节、公式、Unicode、图像和保存后重新打开的结果，不仅检查按钮存在。

`npm run dist:windows:all` 同一份构建生成 EXE、便携包与 MSIX；Linux 配置与跨平台 DEB 脚本也输出当前版本目录。Web 包从已验收构建生成。Android/Harmony 分别构建和冻结云源码，记录平台、版本及构建号，避免相互覆盖。发行前核对包内源码、MSIX 身份与全部有效负载、DEB 控制信息、Web 同域资源，生成 SHA-256 清单。

Android 与 HarmonyOS 继续交付两份独立的云打包源码快照。编辑器和移动 AI 悬浮助手共用一套界面；原生层存在实际差异：Android 使用 Intent / FileProvider 分享文件，HarmonyOS 使用 DocumentViewPicker 与系统文件 API 保存，WebView 消息及启动配置也有平台分支（`mobile/native/share.uts`、`mobile/native/export.uts`、`mobile/pages/workspace/workspace.uvue`）。分别运行对应的 `build`、原生检查和快照流程，平台标识必须与目标一致，不把最后一次构建的静态资源同时当作两个平台的已冻结源码。已发布版本快照保持原校验值；源码功能修改本身不代表已生成或验收新的 APK / App Pack。

Android 云打包源码 ZIP 及其解压后所有文件的总字节数均不得超过 **60,000,000 字节（60 MB）**。运行 `node mobile/scripts/archive-source.mjs android` 时强制检查两项限额、平台、版本、构建号、完整字体字节及 ZIP 全部文件的 CRC / SHA-256；超限或资源混用即失败。源码包名为 `seal-office-${version}-android-cloud-source.zip` 和 `seal-office-${version}-harmony-cloud-source.zip`，由 `build/artifact-names.json` 统一管理，输出到 `release/v${version}/`。

每个平台依次执行 `npm --prefix mobile run build:<platform>`、`npm --prefix mobile run check:<platform>`、生产资源回归、`node mobile/scripts/snapshot.mjs <platform>`、`node mobile/scripts/archive-source.mjs <platform>`，再开始另一个平台。源码 ZIP 解压根目录即 HBuilderX 项目，直接打开并提交对应平台云打包；禁止再把另一个平台构建结果覆盖进去。ZIP 不包含开发依赖、签名私钥或旧安装包，应用身份与签名配置继续沿用。

移动端模板配图使用 `mobile/assets/template-images/` 中的专用派生资源：透明插画保留 PNG 透明通道，照片使用最长边 1280 的 JPEG，字库不裁字。原始桌面配图保持原样；派生图像的 MIME、尺寸、字节数和内容指纹同步生成，保存 / 重开测试须验证资源一致。重建配图可执行 `python mobile/scripts/prepare-template-images.py`（Pillow）；常规构建直接使用已提交的派生资源，不依赖 Python。仅交付移动云打包源码时，不提前把 APK / App Pack 标为已发布成品。单独发布桌面安装包时，仍须完成桌面成品验收并更新双画幅介绍视频；Android 画面可使用已独立验收的冻结快照，明确记录该快照构建指纹，不混入本次桌面构建资源。

## 每版视频

每次正式发布必须同步重制横版 PC（1920×1080）和竖版 Android（1080×1920）介绍视频，放入 `release/promo/`。旧视频、配音、字幕、封面与录制中间件清理，不能继续把旧版片段作为最新版介绍。新视频使用英文文件名和当前版本。

运行 `npm run promo:build`，从当前安装成品与移动生产构建录制，读取 `docs/promo/current-storyboard.json`。分镜展示真实功能、实际保存和手机布局；不得展示不存在的能力或宣称兼容所有未知文件。只使用项目演示资料，账号画面用隔离测试状态；AI 示例必须标注，不能当作真实服务返回。配音只包含公开介绍文本。

当前介绍片必须制作成具体操作教程，逐步展示点击入口、逐字输入、执行命令以及真实结果；不能用静态界面截图轮播代替操作录像。录制时显示鼠标指针、点击圆环和当前目标区域的紫色光晕轮廓，输入直接进入真实编辑器，标注层不得覆盖文字或拦截输入。移动端录制须覆盖真实浏览器触摸输入产生的翻页、双击显示及三秒自动隐藏工具栏、双指缩放结果；仍需如实标注浏览器布局演示，不能称为 APK 真机录像。

用户已在 2026-10-23 听取教程试听并确认 `D:/yewu/女声配音试听.mp3` 对应的重录音色：`zh-CN-XiaoxiaoNeural`、语速 `+5%`、音调 `+4Hz`。当前教程沿用这组参数，使用海豹办公的专用操作文案；原样音哈希 `a13d2c5a81acd7a4e30522958393b21b0478a91ef24165bc4df16d6f82c4aa0b`。不能静默回退到 Windows SAPI 或其他声音。当前可重复入口为 `tutorial-voice.py` → `tutorial-record.cjs` → `tutorial-render.py`，由 `npm run promo:build` 顺序执行，版本仍读取 `package.json`。交付保存实际动作时间线、逐项结果断言、配音及成片哈希，并验证紫色轮廓和逐字输入的画面变化。

完整查看两端联系表和操作细节帧后，执行 `python scripts/promo/tutorial-finalize.py --record-visual-review --clean`，冻结验收记录并清理录制配置、试录和过期短片中间件。此参数记录执行者的画面复核，不表示用户已验收成片。教程素材单独补发可使用 `v<版本>-tutorials` 修订标签与 `scripts/promo/publish-tutorials.py`；提交并推送已验收的生成脚本和证据、创建并推送标签后才上传，逐个匿名下载核对字节与 SHA-256。安装包与历史标签不随视频重制改变。B 站投稿须在实际可控制的登录页面提交并看到投稿结果后才能记为已发布。

同一应用版本内补发移动/Web 修复时，保留已发布的旧快照与旧校验值，新快照使用独立修订标签，最新源码包和解包目录归入 `release/v<版本>/mobile-web/`。视频构建通过 `SEAL_PROMO_ANDROID_ROOT` 显式指定本次通过验收的 Android 快照下 `static/office` 的绝对路径；脚本会验证路径、平台和版本，不能误用此前同版本的旧资源。远端补充发行可使用 `v<版本>-mobile-web` 标签，不移动原版本标签或替换原发行附件。

上段的历史快照保留适用于远端发行与验收记录。本机云打包交付按用户最新要求，只留通过当前验收的 Android / HarmonyOS 各一个 ZIP 和解压项目；旧试包、旧 `verified/` 解压项目及 `mobile/unpackage/cloud-ready/` 中的历史和重复交付快照，在新 ZIP、平台标识和所有解压文件校验通过后清理。删除前确认绝对路径位于项目内；链接只删除链接本身，不遍历其目标；若生成目录中有签名成品，先按原字节另存，再清理生成文件。历史报告和远端历史附件保留。

当前 2.2.0 的唯一 HBuilderX 云打包项目为 `release/v2.2.0/mobile-web/android-cloud-source/` 与 `release/v2.2.0/mobile-web/harmony-cloud-source/`，ZIP 在同级目录。必须同步更新 `release/v<版本>/README.txt`，不保留指向旧 `verified/` 的打包指引。操作说明和核验附件放在项目目录外，干净源码目录必须与其 ZIP 逐文件一致。HBuilderX 编译会产生 `unpackage/`，这些生成文件不计入已交付 ZIP 的解压体积，也不得重新混进云源码归档；交付目录复核时先另存新成品并清理生成文件，再统计全目录大小。Android 的交付 ZIP 和干净解压项目均须不超过 60,000,000 字节。

每次交付收尾时清理本次产生的临时脚本、测试目录、源码暂存、解包副本和编译缓存，先将必要证据写入正式验收记录并核验交付文件，再删除临时内容。不把临时目录留作第二个打包入口；不删除用户原始文件、应用数据或签名凭据。移动端助手的悬浮球必须使用与桌面一致的海豹办公 Logo，成品和云源码的生产浏览器验收均需检查实际图形、触摸拖动和点击打开，不能只检查按钮存在。

交付前检查视频完整解码、画幅、时长、帧率、音轨、字幕和代表性画面；生成封面、字幕及 `verification.json`，记录构建、素材与成片 SHA-256。浏览器录制的 Android 布局必须明确素材来源，不冒称 APK 真机录制。清理脚本只操作确认位于本项目的生成目录，拒绝符号链接和越界路径。

## 发布

提交并推送两端仓库源码、标签与新版本验收报告；发布附件后再核对远端大小和 SHA-256。部署保留现有后台、转换工作进程、加密数据和配置，检查新能力与匿名访问权限。远端历史安装包不因本机仅留最新版而删除；视频替换只处理旧介绍视频附件。
