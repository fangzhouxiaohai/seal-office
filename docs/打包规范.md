# 海豹办公打包规范

版本读取根目录 `package.json`，桌面、服务端、移动端版本与云打包构建号同步；应用身份、签名与现有中文显示名保持。文件名统一读取 `build/artifact-names.json`，微软商店清单两处显示名使用已保留的 `seal-office`。

## 目录

每次打包先运行 `npm run release:prepare`。本机 `release/` 顶层只允许当前 `v<版本>/` 和 `promo/`，只保留一个版本目录；旧版本本机二进制可以清理，远端历史发行与历史验收报告不修改。所有安装包、Web ZIP、移动云打包源码 ZIP、校验文件、`win-unpacked`、`linux-unpacked` 与 MSIX 布局均归入当前版本目录，禁止在 `release/` 顶层单独放安装包。

```text
release/
  v2.1.1/
    seal-office-setup-2.1.1.exe
    seal-office-2.1.1-microsoft-store-x64.msix
    seal-office-2.1.1-amd64.deb
    seal-office-2.1.1-web.zip
    win-unpacked/
    linux-unpacked/
    SHA256SUMS.txt
  promo/
    seal-office-2.1.1-pc-intro-1080p.mp4
    seal-office-2.1.1-android-intro-1080p.mp4
```

Android/Harmony 云服务返回文件须先校验版本、身份、内置资源和签名，再按英文规则归档。不把云打包源码 ZIP 称为 APK/HAP。微软商店上传用未签名 MSIX 与可直接旁加载的已签名 MSIX 分别标明。

四种默认专属后缀为 `.sldoc`、`.slxls`、`.slppt`、`.spdf`，Windows、Linux、Web、Android 和 HarmonyOS 使用同一容器协议。发行验收须覆盖打开、编辑、连续保存、另存为、关闭重开及云端文件入口；旧 `.sealdoc`、`.sealsheet`、`.sealshow` 继续兼容。Windows 右键新建模板必须是有效容器，不能用空文件占位。新增移动桥接修改还须验证真实 SDK 发出的普通 JSON 对象消息与启动握手，浏览器模拟宿主不能冒称原生设备验收。

## 检查与构建

先完成类型检查、渲染层与主进程完整回归、云服务回归、移动桥接检查和生产浏览器分组回归；涉及账号删除还要验证隔离备份、故障重试、其他账号保留和恢复过滤。测试真实字节、公式、Unicode、图像和保存后重新打开的结果，不仅检查按钮存在。

`npm run dist:windows:all` 同一份构建只生成安装程序 EXE 与微软商店 MSIX，不再打包便携版；Linux 配置与跨平台 DEB 脚本也输出当前版本目录。Web 包从已验收构建生成。Android/Harmony 分别构建和冻结云源码，记录平台、版本及构建号，避免相互覆盖。发行前核对包内源码、MSIX 身份与全部有效负载、DEB 控制信息、Web 同域资源，生成 SHA-256 清单。

Android 原 HBuilderX 与 HarmonyOS 仍保留两份独立的云打包源码快照，供旧路径追溯。新版安卓正式 APK 只使用 `android-mobile/android-studio/` 的 Java 本机工程，直接打包 `mobile/static/office/` 的 Android 平台资源；旧 HBuilderX 安卓工程不参与新版 APK 打包。鸿蒙继续使用本机原有打包流程。HBuilderX 命令行无法连接已打开界面时，2.7.0 可运行 `npm --prefix mobile run build:harmony` 和 `node mobile/scripts/repack-harmony-generated.mjs`，对本机 HBuilderX 已生成项目做严格版本核对与资源同步，再以 DevEco Studio 自带 Hvigor 本机分别构建已签名 HAP 与 App Pack；若原生编译片段不符，脚本必须报错停止，不得把旧原生代码混进新包。编辑器和移动 AI 悬浮助手共用一套界面，原生层分别维护系统文件选择、保存、打印、剪贴板、联网及返回键协议。两个平台的资源先独立构建与核对，不能把最后一次构建的资源同时当作两个平台的已冻结源码。源码修改本身不代表已生成或验收新的 APK / App Pack。

本机移动项目固定使用 `mobile/` 工作源码、`android-mobile/` 安卓源码、`harmony-mobile/` 鸿蒙源码三个顶层入口。`android-mobile/` 根目录保留原 HBuilderX 项目，子目录 `android-studio/` 是唯一 Java 本机工程，并加入 Git；不创建其他顶层安卓源码目录。临时快照只用于构建与逐文件校验。`release/v<版本>/mobile-web/` 保存源码 ZIP、校验文件与安装成品，历史远端发行及历史报告不修改。旧 HBuilderX 解包项目不加入 Git，Java 工程生成资源与编译缓存也不加入 Git。

Android 旧云打包源码 ZIP 及其解压后所有文件的总字节数均不得超过 **60,000,000 字节（60 MB）**。运行 `node mobile/scripts/archive-source.mjs android` 时仍强制检查两项限额、平台、版本、构建号、完整字体字节及 ZIP 全部文件的 CRC / SHA-256。新版 Java 本机工程不向 HBuilderX 云服务上传源码，因此不受该付费门槛限制；构建前必须核对编辑器、原生页面、功能依赖和完整字库，禁止为缩小包体删减能力。正式 APK 必须使用与旧版一致的签名证书，保留旧版 `file:///android_asset/apps/__UNI__B52B65B/www/static/office/index.html` 工作台来源，并在保留数据的设备上验证覆盖安装与旧文档重开。安卓构建工具默认忽略以双下划线开头的资源目录，工程已显式调整资源忽略规则；每次用逐文件校验脚本核对 APK 内全部工作台文件。

旧 HBuilderX 平台流程依次执行 `npm --prefix mobile run build:<platform>`、`npm --prefix mobile run check:<platform>`、生产资源回归、`node mobile/scripts/snapshot.mjs <platform>`、`node mobile/scripts/archive-source.mjs <platform>`，再开始另一个平台。安卓 Java 流程先运行 `npm --prefix mobile run build:android`，然后在 `android-mobile/android-studio/` 执行 `.\gradlew.bat testDebugUnitTest assembleDebug` 和 `python scripts/verify-apk.py app/build/outputs/apk/debug/app-debug.apk`，实机或模拟器运行 `node scripts/emulator-smoke.cjs --verify-storage --verify-import`。正式版通过本机环境变量提供签名文件、别名和口令，`verifyReleaseSigning` 核对旧版证书指纹后执行 `assembleRelease`，再用逐文件脚本和安卓签名工具核验成品。私钥、密码及旧安装包不提交仓库。

移动端模板配图使用 `mobile/assets/template-images/` 中的专用派生资源：透明插画保留 PNG 透明通道，照片使用最长边 1280 的 JPEG，字库不裁字。原始桌面配图保持原样；派生图像的 MIME、尺寸、字节数和内容指纹同步生成，保存 / 重开测试须验证资源一致。重建配图可执行 `python mobile/scripts/prepare-template-images.py`（Pillow）；常规构建直接使用已提交的派生资源，不依赖 Python。仅交付移动云打包源码时，不提前把 APK / App Pack 标为已发布成品。单独发布桌面安装包时，仍须完成桌面成品验收并更新双画幅介绍视频；Android 画面可使用已独立验收的冻结快照，明确记录该快照构建指纹，不混入本次桌面构建资源。

## 每版视频

每次正式发布必须同步重制横版 PC（1920×1080）和竖版 Android（1080×1920）介绍视频，放入 `release/promo/`。旧视频、配音、字幕、封面与录制中间件清理，不能继续把旧版片段作为最新版介绍。新视频使用英文文件名和当前版本。

运行 `npm run promo:build`，从当前安装成品与移动生产构建录制，读取 `docs/promo/current-storyboard.json`。分镜展示真实功能、实际保存和手机布局；不得展示不存在的能力或宣称兼容所有未知文件。只使用项目演示资料，账号画面用隔离测试状态；AI 示例必须标注，不能当作真实服务返回。配音只包含公开介绍文本。

2.6.0 的电脑横版单独制作时，运行 `npm run promo:build -- --pc-current`，读取 `docs/promo/pc-current-storyboard.json`。录制使用 2.6.0 生产 Web 界面、独立导入的 Zotero 演示文献、本机隔离云服务与演示账号、隔离文档及录制专用剪贴板桥接。云链接可在本机匿名访问接口验证，画面不使用用户现有云文件；助手仅演示当前文件范围和任务输入，不伪造 AI 结果。渲染输出先保留旧视频，完整解码、联系表与代表性画面复核通过后，将 `release/promo/verification.json` 的 `visualReview` 设为“通过”，再运行 `node scripts/promo/pc-current-finalize.cjs` 归档操作记录、更新校验文件并清理旧版宣传素材与本次录制中间件。此单独电脑视频任务不等同于正式发行所需的双画幅验收。

当前介绍片必须制作成具体操作教程，逐步展示点击入口、逐字输入、执行命令以及真实结果；不能用静态界面截图轮播代替操作录像。录制时显示鼠标指针、点击圆环和当前目标区域的紫色光晕轮廓，输入直接进入真实编辑器，标注层不得覆盖文字或拦截输入。移动端录制须覆盖真实浏览器触摸输入产生的翻页、双击显示及三秒自动隐藏工具栏、双指缩放结果；仍需如实标注浏览器布局演示，不能称为 APK 真机录像。

用户已在 2026-10-23 听取教程试听并确认 `D:/yewu/女声配音试听.mp3` 对应的重录音色：`zh-CN-XiaoxiaoNeural`、语速 `+5%`、音调 `+4Hz`。当前教程沿用这组参数，使用海豹办公的专用操作文案；原样音哈希 `a13d2c5a81acd7a4e30522958393b21b0478a91ef24165bc4df16d6f82c4aa0b`。不能静默回退到 Windows SAPI 或其他声音。当前可重复入口为 `tutorial-voice.py` → `tutorial-record.cjs` → `tutorial-render.py`，由 `npm run promo:build` 顺序执行，版本仍读取 `package.json`。交付保存实际动作时间线、逐项结果断言、配音及成片哈希，并验证紫色轮廓和逐字输入的画面变化。

完整查看两端联系表和操作细节帧后，执行 `python scripts/promo/tutorial-finalize.py --record-visual-review --clean`，冻结验收记录并清理录制配置、试录和过期短片中间件。此参数记录执行者的画面复核，不表示用户已验收成片。教程素材单独补发可使用 `v<版本>-tutorials` 修订标签与 `scripts/promo/publish-tutorials.py`；提交并推送已验收的生成脚本和证据、创建并推送标签后才上传，逐个匿名下载核对字节与 SHA-256。安装包与历史标签不随视频重制改变。B 站投稿须在实际可控制的登录页面提交并看到投稿结果后才能记为已发布。

同一应用版本内补发移动/Web 修复时，保留已发布的旧快照与旧校验值，新快照使用独立修订标签。最新源码 ZIP 和安装成品放入 `release/v<版本>/mobile-web/`，解包项目仅放入仓库根目录的 `android-mobile/` 与 `harmony-mobile/`。视频构建通过 `SEAL_PROMO_ANDROID_ROOT` 显式指定本次通过验收的 Android 项目下 `static/office` 的绝对路径；脚本会验证路径、平台和版本，不能误用此前同版本的旧资源。远端补充发行可使用 `v<版本>-mobile-web` 标签，不移动原版本标签或替换原发行附件。

上段的历史快照保留适用于远端发行与验收记录。本机云打包交付只留通过当前验收的 Android / HarmonyOS 各一个 ZIP 和根目录的两个固定解包项目；旧试包、旧 `verified/` 解包项目及 `mobile/unpackage/cloud-ready/` 中的历史和重复交付快照，在新 ZIP、平台标识和所有解压文件校验通过后清理。删除前确认绝对路径位于项目内；链接只删除链接本身，不遍历其目标；若生成目录中有签名成品，先按原字节另存，再清理生成文件。历史报告和远端历史附件保留。

当前版本的唯一 HBuilderX 打包项目为 `android-mobile/` 与 `harmony-mobile/`，源码 ZIP 在 `release/v<版本>/mobile-web/`。必须同步更新 `release/v<版本>/README.txt`，不保留指向旧 `verified/` 的打包指引。操作说明和核验附件放在项目目录外，干净源码目录必须与其 ZIP 逐文件一致。HBuilderX 编译会产生 `unpackage/`，这些生成文件不计入已交付 ZIP 的解压体积，也不得重新混进云源码归档；交付目录复核时先另存新成品并清理生成文件，再统计全目录大小。Android 的交付 ZIP 和干净解压项目均须不超过 60,000,000 字节。

每次交付收尾时清理本次产生的临时脚本、测试目录、源码暂存、解包副本和编译缓存，先将必要证据写入正式验收记录并核验交付文件，再删除临时内容。不把临时目录留作第二个打包入口；不删除用户原始文件、应用数据或签名凭据。移动端助手的悬浮球必须使用与桌面一致的海豹办公 Logo，成品和云源码的生产浏览器验收均需检查实际图形、触摸拖动和点击打开，不能只检查按钮存在。

交付前检查视频完整解码、画幅、时长、帧率、音轨、字幕和代表性画面；生成封面、字幕及 `verification.json`，记录构建、素材与成片 SHA-256。浏览器录制的 Android 布局必须明确素材来源，不冒称 APK 真机录制。清理脚本只操作确认位于本项目的生成目录，拒绝符号链接和越界路径。

## 发布

提交并推送两端仓库源码、标签与新版本验收报告；发布附件后再核对远端大小和 SHA-256。部署保留现有后台、转换工作进程、加密数据和配置，检查新能力与匿名访问权限。远端历史安装包不因本机仅留最新版而删除；视频替换只处理旧介绍视频附件。
