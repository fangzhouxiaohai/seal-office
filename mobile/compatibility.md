原生编辑器使用系统 WebView。Android 版本与网页内核版本是两个独立条件：本项目构建基线为 Chromium 100+ / Safari 15.4+，启动时同时检查存储、加密、structuredClone、数组索引和布局能力。旧内核提供明确的系统组件更新入口，不将 Android 9 默认旧 WebView 标成完整支持。UA 条件单元测试只是启动判断测试，不是实际 iOS 或安卓设备测试。

Android 16 的预测返回默认行为变化会影响旧返回拦截。项目通过根目录 `AndroidManifest.xml` 暂时设置 `enableOnBackInvokedCallback=false`，保护未保存文档；后续迁移预测返回时必须再次验收返回、退出及手势取消。原生外壳在 onReady / onResize 读取安全区；浏览器根据 visualViewport 和焦点处理键盘，不把双指缩放误判为键盘。

鸿蒙 4 等可以运行 APK 的设备，走 Android 兼容路径；HarmonyOS NEXT 的原生 HAP 单独验收，不能用 APK 测试结果替代。

## 每个入口的操作要求

生产浏览器回归逐一点击“功能”中的 15 个入口：首页、最近、星标、我的云空间、知识库、演示模板市场、云空间回收站、PDF 工具、脑图、流程图、日历、应用、应用文档空间、设置、帮助手册。检查菜单关闭、导航选中状态、目标页面、页面异常与横向溢出。设置、帮助和 PDF 必须进入对应模块，不能只改变首页筛选键。

底部的首页、文件、助手、功能，以及新建文字、表格、演示和 PDF 分别验收。编辑按钮不能只以“存在”作为通过标准：表格公式栏提交需实际写入单元格；演示拖动需改变对象坐标；文字输入与恢复需保留正文。演示手势取消和双指介入不得写入错误位置，触屏双击进入文本编辑。中文输入法候选回车不触发表格提交。

## 重新云打包后的验收

默认仍只打包 Android。HBuilderX 的 GUI 已运行，但本机 CLI 当前不能识别其运行实例；未据此声称新 APK 已打好。GUI 可以发行 `mobile` 项目的 Android 云包。

```powershell
npm run mobile:build
npm --prefix mobile run check
npm --prefix mobile run check:android
# GUI 云打包下载 APK 后：
npm --prefix mobile run check:apk -- D:/downsoft/新包.apk --device emulator-5554 --require-current
```

验包会检查包内编辑器是否与当前构建一致、签名、SDK/ABI 和 arm64 ELF 对齐；`--device` 只读已安装包哈希，不安装或覆盖 App。随后安装新包，重新验收桌面 Logo、系统分享、DOCX/Markdown 文件选择、软键盘、安全区、返回与恢复。旧 APK 的成功项保留为旧版本证据，不能转写成新包已通过。
