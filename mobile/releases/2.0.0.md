## 第四轮发行文件命名

按用户最新要求，今后的安装包与分发归档统一使用英文文件名。本版 Android 归档为 `seal-office-2.0.0-android.apk`，鸿蒙归档为 `seal-office-2.0.0-harmony.hap`。云服务仍可能返回其默认下载名；仓库只控制验证后的本地归档名，不修改或重新签名包内字节，也不修改应用界面名称。历史验收与历史包名保留原记录。

```powershell
# 云包下载后执行；保留原下载文件，拒绝覆盖内容不同的已有归档。
npm --prefix mobile run check:apk -- "APK绝对路径" --require-current --archive "E:\seal-office\release\v2.0.0"
npm --prefix mobile run check:hap -- "HAP绝对路径" --archive "E:\seal-office\release\v2.0.0"
```

Android 归档必须通过 SDK 签名、版本、包名、16 KiB 配置及当前编辑器资源校验。鸿蒙归档核对 entry HAP 的 ZIP CRC、bundleName、版本和当前鸿蒙云打包快照的内置资源；**不代替鸿蒙签名工具或设备安装验证**，其报告中的 `signatureVerified` / `deviceVerified` 保持 `false`。输入 `.app`、源码 ZIP 或 Android 资源会明确失败。归档的 SHA-256 与原下载文件一致，云包尚未提供时不生成虚构 APK / HAP。

## 本版移动阅读更新

- 手机及触屏平板导入文字文档后默认进入阅读模式，新建文档默认进入编辑模式；顶部可随时切换。
- 阅读模式关闭正文、页眉与页脚编辑，隐藏编辑功能区、图片修改工具和格式浮窗，保留选择复制、目录、查找与滚动阅读。
- 提供 16、18、20、22、24、28、32 阅读字号并记住偏好。正文按窄屏重排，长表格可在表格内横向滚动。
- 外接键盘可用 `Ctrl+Alt+R` 切换手机阅读与编辑，快捷键可在设置中修改。
- 阅读字号、重排和模式切换只改变屏幕显示，不写入原始 HTML、页眉页脚、纸张、分栏或导出格式；返回编辑后使用原有文档格式与撤销栈。

共用 Office 引擎的本版变更以仓库正式更新说明为准，不把尚未覆盖的 WPS 功能列为已支持。

- Word 增加全屏横向阅读页、左右滑动与双指缩放，按屏幕重排的阅读页有明确标识；PDF 使用真实文档页面，支持横向分页、双指缩放、全屏及图标切换连续阅读。

## 共用办公兼容与快捷键更新

- XLSX 导入保留公式原文、共享公式、数组公式范围及可读取的结果缓存。本地未支持的函数保留公式和缓存并显示兼容提示，避免保存时将公式清空；外部数据、宏及尚未覆盖的函数仍有明确边界。

- 文字、表格、演示和 PDF 的常用快捷键通过统一调度调用现有功能，支持在设置中修改、检查冲突和恢复默认。可用范围以设置中的命令清单为准。
- 表格单元格输入和查找遵守中文输入法组合状态，确认候选词时不提前提交、移动单元格或触发查找快捷动作。
- PPT 文本框编辑中可直接使用快捷键保存或另存为，保留最新文字、换行、emoji、扩展汉字和组合字符。

## Android 云打包

在 `E:\seal-office` 执行：

```powershell
npm run mobile:build
npm --prefix mobile run check
npm --prefix mobile run typecheck
npm --prefix mobile run check:android
npm --prefix mobile test
npm --prefix mobile run test:browser
npm --prefix mobile run test:browser -- --file
```

使用 HBuilderX 打开 `E:\seal-office\mobile`，核对 manifest 版本 `2.0.0 / 20000`，在“发行 → 原生 App-云打包”选择 Android，沿用原应用的签名方式。构建资源应包含 `static/office/index.html`、`office.js`、`build-info.json` 和本地字体。APK 下载后可执行 `npm --prefix mobile run check:apk -- "APK绝对路径" --require-current`，并在设备上验证升级保留已有文档、文件选择、保存、导出、后台恢复与阅读切换。

## 鸿蒙云打包

```powershell
npm --prefix mobile run build:harmony
npm --prefix mobile run check:harmony
npm --prefix mobile run test:browser -- --file
```

HBuilderX 打开同一移动项目，核对 `app-harmony` 的原 bundleName 与签名配置，使用鸿蒙发行入口提交云打包。构建鸿蒙资源后 `static/office/build-info.json` 的 platform 应为 `harmony`。不要把 Android 生成的原生代码输出当作鸿蒙包；鸿蒙生成包需独立安装验证。

需要重新打 Android 时先再次运行 `npm run mobile:build`，使内置资源的平台标识与目标一致。两端均不得更换已有应用身份和签名。

## 本轮生成的云打包项目快照

完成构建后分别保留 `mobile/unpackage/cloud-ready/2.0.0/android/` 与 `mobile/unpackage/cloud-ready/2.0.0/harmony/`。每个目录包含原生外壳、原有应用身份与签名配置、各端图标及该平台的内置编辑器资源，可单独用 HBuilderX 打开并提交对应平台云打包，避免切换平台时覆盖资源。`snapshot-info.json` 记录文件 SHA-256；快照与原生编译检查均不等于正式 APK / HAP。

重建快照可在原项目完成对应平台构建后运行 `node mobile/scripts/snapshot.mjs android` 或 `node mobile/scripts/snapshot.mjs harmony`。为保留可核验的发布内容，脚本遇到已存在的同版本快照会拒绝覆盖。
