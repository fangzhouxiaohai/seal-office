# 2.0 协作服务实现与部署边界

现有个人云空间、恢复密钥封装、加密文件及分块上传接口保持兼容。`GET /v1/capabilities` 新增 `collaboration: 1`；客户端在调用协作功能前检查能力，旧服务器明确返回“尚未开通协作接口”，不会回退为模拟成功。

| 功能 | 本次实现 | 权限及限制 |
| --- | --- | --- |
| 共享 | 创建、发出/收到列表、接受凭证、下载、修改、撤销 | 绑定已开通云空间的接收账号；只读/编辑；默认 7 天，最多 30 天；保存须携带下载版本，冲突返回 409 |
| 我的设备 | 当前设备注册、会话列表、重命名、撤销设备的所有会话 | 只操作本人设备；撤销当前设备会清除客户端登录状态；接收上传正文后再次检查会话 |
| 标签 | 加密名称和颜色、增删改、关联文件、筛选、关联计数 | 个人账号隔离；最多 200 个标签，每文件最多关联 50 个 |
| 团队 | 创建/重命名/删除、成员、角色、一次性邀请、加密目录/文件、版本化保存 | owner/admin/editor/viewer；owner 管理 admin，admin 仅管理 editor/viewer；viewer 只读；所有写入由服务器重新鉴权 |

团队角色作用于整个团队，尚未提供独立的文件夹 ACL。文字、表格和演示现支持下述加密实时协作与在线成员，PDF 保持独立副本编辑。团队文件删除为明确的删除操作，暂未提供团队回收站界面。尚未启用实时房间的文件保留乐观版本发布；启用后旧整文件发布返回 409，避免覆盖实时内容。单次协作内容上传上限为 100 MiB；个人与团队密文、版本、加密元数据计入团队所有者的既有云空间配额。团队暂限每人 20 个、每团队 100 个成员及 500 条邀请记录。

共享凭证分别包含随机的访问令牌和独立解密密钥。服务端只保存访问令牌的 SHA-256、绑定账号、有效期和加密信封；请求不会上传凭证里的解密密钥。文件仍使用原文件密钥加密，没有生成公开明文副本。团队使用独立随机密钥，成员密钥由各自个人根密钥封装；邀请信封用邀请凭证的独立密钥加密。标签名称、团队名称、目录名称、文件名和正文均由客户端加密。服务端仍知道账号、成员关系、对象数量、角色、时间及密文长度。

邀请只生成可复制凭证，不发送短信、邮件或站内消息。公开 Web 入口可用 `https://seal.xingmasoft.com/office/`，API 保持同域 `/api/v1/` 反向代理；凭证链接只可放 URL fragment，由客户端本地提取，不得放 query/path 或提交至访问日志。后台既有入口保留。

撤销后拒绝新的服务器访问和提交；已经下载、解密或开始传输的副本无法远程收回。团队移除成员后不会假称其本地密钥与副本已销毁。

## 迁移与回滚

迁移只新增协作表，`sessions` 保持原有 `hash,user_id,expires` 三列。设备元数据放独立 `session_devices` 表，以兼容旧服务使用的三列位置插入。旧个人节点、密文、恢复封装及版本不重写。团队密文放 `team-objects/`，与个人 `objects/` 分开，避免旧服务启动时的孤立文件清理误删团队文件。

部署前停止写入并对整个数据目录取得一致备份，包含 `seal.sqlite`、`objects/`、`incoming/`、`team-objects/` 和原有私密运行文件；备份保持服务账号权限。启动新服务后验证能力、旧账号下载及两个测试账号的协作授权。部署工作由维护流程执行，本次测试没有连接生产账号或修改生产密钥。

回滚应停止新服务并切回旧服务代码，保留整个数据目录及新增表/目录。旧服务无法提供新协作功能，客户端会因能力缺失明确失败。旧服务不会计算团队占用，也不了解团队生命周期，因此回滚期间应暂停协作相关写入与云空间清空操作；不能删除新增表或仅恢复旧 SQLite 而保留一部分新对象。如果要求回到部署前状态，必须在停机后恢复整份一致备份，并另存部署后的完整目录以保留新增数据。

## 本机验证

`npm --prefix server test` 包含真实 HTTP/AES 客户端集成、双/三账号授权、撤销/到期/越权、并发接收正文时撤权、乐观冲突、配额及真实旧 SQLite 结构迁移/重启测试。`main/ipc/cloudChannel.collaboration.test.js` 另验证真实 IPC 调用、应用私有下载副本、冲突时本机内容保留与撤权后的下载失败。测试使用隔离临时目录及短信替身，没有外发真实邀请。

## 已登录账号文档转换网关

`capabilities.accountConversion: 1` 表示支持 `GET /v1/conversion/capabilities` 和 `POST /v1/conversion/convert`。请求使用普通云账号 session，需开通云空间；转换不要求解锁个人根密钥。每次发送文档仍须用户明确确认，POST 必须含 `consent: true`。主服务只转发白名单中的输入/输出格式、类型和 Base64 内容，不接受路径、URL、管理指令或外部服务地址。

主服务执行每账号每分钟最多 6 次、同时 1 次的限制，并限制网关最多 4 个未完成请求。单文件最多 20 MiB。它通过回环控制通道调用工作进程的 `/internal/capabilities`、`/internal/convert`，工作进程在验证控制令牌后注入仅存在于本进程内的随机网关凭据，再交给同一个转换实例，因而与原有手动服务令牌客户端共享转换槽位、启停状态和格式校验。管理员访问令牌仍仅保存哈希，不会因账号网关新增明文服务令牌。普通账号无法调用管理接口或修改转换配置。

客户端断开、网关超时或会话撤销会取消工作进程请求，并将取消信号传到 LibreOffice 子进程组，随后删除临时目录。原文件保持不变。转换工作进程的任务记录仅含格式、大小、状态和时间，不保存正文。服务不可用、忙碌、格式错误、超时等通过真实状态码返回。内部控制通道错误被报告为 503，避免误将正确云账号注销；真实会话撤销仍返回 401。

账号网关默认超时 100 秒，LibreOffice 转换上限 90 秒，客户端等待 110 秒。生产 Nginx 的 `/api/v1/conversion/` 路由应允许至少 30 MiB JSON 正文和 120 秒读写等待，并保留原管理入口及手动令牌转换入口。新主服务和 managed 工作进程需要一起升级；若只升级主服务，旧工作进程会被明确识别为需要升级。网关没有新增数据库列或持久令牌，回滚时旧客户端和原手动令牌模式仍可继续使用。


## 加密实时共同编辑（realtime: 1）

`GET /v1/capabilities` 的 `realtime: 1` 表示支持实时协议第 1 版。共享与团队统一按文件建立房间：同一个个人文件的多个共享凭证使用同一房间，接收者仍按各自凭证和账号授权。所有者撤销最后一项共享后仍可从个人云空间读取与编辑自己的实时内容，接收者立即失去后续访问。

路由前缀为 `/v1/realtime/share/:shareId/` 与 `/v1/realtime/team/:teamId/:nodeId/`：

| 方法与后缀 | 行为 |
| --- | --- |
| `POST open` | 写入者首次提交加密 seed；已初始化时返回现有内容。只读者不创建房间。 |
| `GET updates?after=N&initial=1` | 只读快照，返回 seed、必要 checkpoint、最多 256 条顺序日志与加密在线状态；没有房间则返回 initialized:false。后续分页不需 initial。 |
| `GET updates?after=N&wait=10000` | 可选最长 10 秒等待；每 250ms 重验会话与权限，断开后结束。全局最多 256 个等待、每账号最多 4 个。 |
| `POST updates` | operationId + cipher 幂等追加。相同 ID 不同密文返回 409；每条密文最多 8 MiB。 |
| `PUT checkpoint` | 仅 after 等于当前 head 时接受完整加密 CRDT 状态；客户端只压缩已确认服务端日志，不夹带尚未发布的本机队列。 |
| `PUT/DELETE presence` | 会话归属的 clientId 与加密状态，最多 100 在线设备；45 秒无更新过期。 |

正文和格式在客户端使用 Yjs 13.6.33 CRDT 合并。Word 使用结构化 Y.Xml 树、段内文字及独立格式标记；不会按 HTML 标签字符串交错。原生 DOCX 来源包独立保存为原子多值寄存器，顺序接受/拒绝修订可替换，并发替换不同来源包时明确报告结构冲突并保留各自本机版本，停止自动覆盖。Sheet 只传源格、公式、结构和格式，派生值与溢出子格由本机引擎重算。PPT 按稳定对象 ID 合并字段，图片字节随独立加密资源传输。撤销仅追踪本地 CRDT 操作；远端输入不进入本地撤销历史。提供在线成员与设备状态，不宣称远程字符光标完整定位。

密钥不会交给服务器；AES-GCM 加密的 seed、操作、checkpoint 与 presence 以房间/操作/序列/设备为附加认证上下文。服务器知道账号、角色、房间、序号、长度和时间。更新日志最多 4096 条或 48 MiB；客户端在合并 128 条后尝试 checkpoint，单状态最多 24 MiB。幂等回执保留最近 8192 个序列。所有密文、seed/checkpoint 与回执开销计入所有者配额；超限明确失败，本机待发修改保留。Yjs tombstone 或来源包增长仍可能达到 24 MiB 上限，此时必须另存副本，不能无限增长。

桌面安全存储与移动/Web 的受保护本机存储封装离线队列；首次连接尚未成功的输入也保存 base/next 草稿，重新连接后基于原始基线合并。队列在持久化成功后才确认本机落盘，最多 2048 条/32 MiB。浏览器存储被清除、配额满或所有解锁密钥丢失不能保证恢复，界面会报告失败并允许另存文件。不同账号与文件密钥独立隔离，同账号多窗口写安全缓存时合并完整 CRDT 状态。

### 最新下载与 sourceFile 边界

服务端文件 `/content` 及个人 `versions` 仍保留原始加密办公包作为 sourceFile；实时修改在独立密文日志中，服务器无法直接生成最新办公包。共享、团队、我的云空间和标签打开入口先读取 sourceFile，再用只读实时 snapshot/pull 合并全部分页，在客户端真实生成 DOCX/XLSX/PPTX 并写入应用私有副本。PPT 初始资源从 sourceFile 恢复，后续资源从加密 CRDT 恢复；缺资源或 codec 拒绝有损写回会停止下载，绝不把 seed 当最新文档冒充成功。历史版本下载保持明确的历史语义。个人云“复制”也从物化后的最新文件创建独立节点。旧服务层复制/公开发布调用若遇正在实时协作的文件会明确拒绝，并要求先下载最新副本再上传公开，避免发布过时 sourceFile。未经升级的第三方调用者只读 `/content` 得到 sourceFile，必须使用此实时协议自行物化，不应把它当作当前实时版本。

实时房间启用后个人分块上传初始化/提交、共享及团队整文件发布均返回 409，防止旧客户端覆盖 seed。降权只读仍可查看获准内容，不能提交新更新或 checkpoint；撤权、到期、设备撤销和停用在每个请求及长轮询期间重新检查。离线已解密副本无法收回，已在传输中的字节也不能撤回。协作状态和待发本机内容保留，另存为新路径后成为独立副本。

新增 SQLite `realtime_rooms/updates/receipts/presence` 表只保存密文与元数据，不修改旧表列。备份必须包含整个 SQLite；旧代码不理解实时日志，回滚必须暂停实时文档写入并完整保留新增表，不能仅回退旧办公包来覆盖最新实时内容。部署同时升级后端与三端客户端；旧服务器明确报告 501 能力缺失并显示原有显式版本发布入口。
