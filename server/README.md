# 海豹办公云服务 2.1.1

客户端默认连接 `https://seal.xingmasoft.com/api`，也可在账号设置中连接兼容的 HTTPS 服务。Node.js 20 及以上运行 `npm ci --omit=dev && npm start`。服务监听回环地址；通过宝塔站点 Nginx 反向代理提供 HTTPS。管理页面使用固定版本 Panshi 前端基础，构建方法见 [来源与许可证](admin/PROVENANCE.md)。

## 服务配置

通过系统服务的 `SEAL_ENV_FILE` 指定仅运维账号可写的环境文件。生产配置不入库；不要将文件复制到客户端。变量：

| 变量 | 用途 |
| --- | --- |
| `PORT` | 回环监听端口，默认 8096 |
| `SEAL_DATA_DIR` | 数据目录，服务账号需读写，其他用户不可读取 |
| `ALIYUN_ACCESS_KEY_ID` / `ALIYUN_ACCESS_KEY_SECRET` | 阿里云短信访问凭据，仅服务端 |
| `SMS_SIGN_NAME` / `SMS_TEMPLATE_CODE` | 审核完成的签名和验证码模板 |
| `SEAL_ADMIN_SALT` / `SEAL_ADMIN_PASSWORD_HASH` | 管理员密码盐及 scrypt 派生的 32 字节十六进制哈希 |
| `SEAL_ERASURE_DIR` | 独立于可恢复数据目录的注销凭据账本，必须持续保留 |
| `SEAL_BACKUP_DIR` | 本服务管理的完整备份根目录，注销完成前清理其中对应账号的数据 |
| `SEAL_ERASURE_BACKEND` | 默认由 API 派生清理进程；生产备份由 root 管理时设为 `systemd` 并安装受限清理服务 |

每账号上限 300,000,000 字节。文件密文、版本、回收站、加密元数据、公开副本与公开索引计入用量；并发上传通过预留用量控制。上传块 1 MiB，24 小时未提交的上传会清理；回收站保留 30 天。接收新数据前检查磁盘余量，预留 2 GiB 运维空间。此部署使用 sql.js 持久化 SQLite，适用于初始部署；须监控进程内存和数据库体积，在扩大用户规模前迁移到独立持久化数据库并进行负载验收。

## 隐私和公开资料

私有文件、名称、索引在客户端以 AES-256-GCM 加密；每文件独立密钥由用户根密钥封装。恢复密钥不上传服务器。服务器仍可知道手机号、密文大小、时间与对象数量。桌面设备的密钥和会话由操作系统安全存储保护；系统安全存储不可用时拒绝保存密钥。

云空间与自动保存默认关闭，需要各自主动开启。公开发布须另行授权，生成供管理员审核的明文公开副本；这是私有加密存储以外的一条路径。公开文件最多 10 MiB。后台采用隔离工作线程验证格式、签名、宏、路径、XML 实体和解压大小，不能等同于通用杀毒引擎。撤回或删除后立即拒绝公开访问并清除公开原文件和索引。已经被他人下载的副本无法收回。

AI 沿用用户当前配置的服务。各端实际生成前使用当前登录会话在线请求 `GET /v1/ai/identity`，只有通过短信创建的手机号账号才能获得最小身份核验结果。密码登录只认证已有账号。身份核验不要求开通或解锁云空间，结果不包含手机号或验证码，也不进入第三方模型参数。匿名、过期、撤销和核验失败时拒绝生成。私有检索在客户端进行，选定片段或扫描页仅在单次授权后发送给该 AI 服务，云端管理后台不持有用户的 AI 凭据和资料明文。法规依据及边界见[AI 身份核验](../docs/AI身份核验.md)。

公开知识库支持四种新专属格式和三种旧专属格式；公开演示模板可保留 SLPPT、SEALSHOW 或 PPTX。原生格式复用桌面的容器、大小、CRC 和 SHA-256 校验，并检查 HTML/SVG、保留的 OOXML 包及 SPDF 中的活动内容。此检查不改变私有文档字节，也不代替通用安全扫描。

## 部署、备份和回滚

`deploy/` 提供独立的 Nginx 站点、非 root API 服务、每日备份、每小时健康检查和只针对本域名的证书续签任务。按实际项目目录调整配置再安装；勿覆盖已有其他站点。站点目录结构：

完整仓库直接读取 `main/documentFormats.json` 和 `main/office/sealFormat.js`。若单独部署服务目录，须将它们分别复制为服务根目录的 `documentFormats.json` 和 `nativeSealFormat.cjs`，与服务代码一起记录 SHA-256；缺少编解码器时启动失败，不能跳过原生文件校验。先发布支持 `aiIdentity: 1` 的后台，再发布要求此能力的前端。会话、数据、注销账本、环境文件和管理员页面均保留，切换前在独立端口核验匿名身份接口返回 401。

```text
/www/wwwroot/seal.xingmasoft.com/
  releases/<发布版本>/    服务代码及 admin/dist
  current -> releases/<发布版本>
  admin -> current/admin/dist
  data/                  持久化数据，权限 0700
```

备份保存到 `/www/backup/seal-cloud`，目录权限 0700、文件权限 0600，保留最长 7 天。备份脚本暂停本服务取得一致副本，恢复后检查就绪；仅操作海豹办公服务。恢复演练须在独立目录和端口进行，先核对 SQLite 和对象文件，再用用户恢复密钥验证下载解密。不得将备份直接覆盖生产数据。回滚切换 `current` 至前一兼容发布目录并重启本服务，保留 `data`、独立注销账本和环境文件。已经执行注销后，不可直接回滚到不读取注销账本的旧服务。

## 登录密码与永久注销

短信登录继续可用。用户登录后可用当前密码或绑定手机的专用验证码设置、修改密码；密码使用带随机盐的异步 scrypt 派生，客户端不保存登录密码。改密会撤销其他会话。登录密码与云空间恢复密钥独立，密码不能替代遗失的恢复密钥。

注销需要已登录的账号、用途独立的短信验证码及完整确认文字。API 先写入独立账本，再删除活动数据库、密文对象和账号拥有的团队，撤销所有会话；备份清理完成前仅报告“处理中”。注销回执可在会话失效或客户端重启后继续查询。账号加入的他人团队保留，相关署名匿名化；已被他人下载的副本和用户本机文档不在服务器删除范围内。

生产服务以 `seal-cloud` 用户运行，历史备份由 root 保管。安装 `deploy/seal-cloud-erasure.service` 和 `.path`，清理进程仅允许写备份目录及独立账本，不写活动数据库。独立账本建议位于 `/www/wwwroot/seal.xingmasoft.com/account-erasure`，属主 `root:seal-cloud`、权限 0770；API 的 systemd drop-in 额外允许写入此目录。设置以上三个环境变量，完成 `systemd-analyze verify` 后启用路径单元。部署前应在隔离目录实测 API 用户写账本、受限清理服务处理合成备份，以及失败仍保留待处理状态。

恢复或迁移时，先停止 API、注销路径单元和正在运行的清理单元，将独立账本与备份分别保存，绝不能用旧备份覆盖账本。恢复数据库和对象后，核对活动数据目录属主为 `seal-cloud:seal-cloud`，目录 0700、私有文件 0600；由 root 清理过的备份文件不会自动继承 API 的属主。让新版 API 先读取完整账本、重新执行已注销账号的清理，再开放入口并启动路径单元。新增备份位置也须纳入 `SEAL_BACKUP_DIR`；不在此目录内的运维副本必须在报注销完成前另行清理。备份包含未知结构、符号链接、未完成归档或清理失败时，服务保持待处理状态，运维修复后重试，不得手动把账本改成已完成。

证书由免费证书服务签发，安装到宝塔站点证书目录。`seal-cloud-cert.timer` 每日检查本域名续签，健康检查在剩余有效期不足 14 天时失败。通过 `systemctl status`、系统日志和站点错误日志排查；服务日志不打印短信凭据、验证码或私有内容。

## 验证

运行 `npm test`。集成用例使用临时目录和隔离的短信替身，覆盖真实加密客户端、双设备冲突、并发上传、断网、重启、过期、撤权、配额、停用和备份恢复，以及文档转换管理、令牌隔离和轮换、暂停、并发与任务元数据。管理员概览接口只返回 `138****0000` 形式的脱敏手机号，页面同时做显示保护；搜索使用可见号码片段或账号标识。真实短信收取需要业务提供测试手机号，测试替身不会部署到生产入口。

文档转换托管于本项目后台，工作进程使用独立的非 root 运行环境，手机通过 HTTPS 接口连接。常用格式离线处理，旧版文字和演示按单次上传确认转换；转换服务不读取已有私有云盘密文。部署与回滚见[后台文档转换部署与验收](../docs/后台文档转换部署与验收.md)。
